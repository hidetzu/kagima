# 実証実験の手順 — 本物のカメラ・HTTPS・別ネットワーク

⚠ **これは製品構成の決定ではない。** ⚠ **「何が起きるかを観測する」ための手順である。**

⚠ **答えたい問いは 1 つ:**
⚠ **STUN だけで、実際に異なるネットワークにいる 2 人のあいだで、映像が流れて 30 秒保つのか。**
⚠ **これは [`adr/0001`](adr/0001-keep-media-peer-to-peer-and-off-our-servers.md) が
先送りにした TURN の判断([kagima#16](https://github.com/hidetzu/kagima/issues/16))の材料である。**

## ⚠ 0. この観測が言えないこと

⚠ **最初に書いておく。** ⚠ **これを守らないと、観測は数字だけが独り歩きする。**

- ⚠ **「到達率」とは呼ばない。** ⚠ **試した組み合わせでの観測結果である。**
  ⚠ **分母は「試した回数」であって、⚠ 世の中のネットワークではない**
  ([`../.claude/rules/evidence.md`](../.claude/rules/evidence.md))。
- ⚠ **成功しても「STUN で足りる」とは言えない。** ⚠ **言えるのは「この組み合わせでは足りた」まで。**
- ⚠ **失敗しても「TURN が要る」とは言えない。** ⚠ **失敗の種類を分けるまでは、何も言えない**(§ 5)。
- ⚠ **観測しなかったことは、起きなかったことではない。**
  ⚠ **試していない回線(会社の NAT、公衆 Wi-Fi、CGNAT、モバイルの別キャリア)については沈黙する。**

## 1. なぜトンネルが要るのか

⚠ **カメラは secure context でしか開かない。** ⚠ **これは測ってある:**

| 開き方 | `navigator.mediaDevices` |
|---|---|
| `http://127.0.0.1:8787` | ⚠ **ある**(loopback は secure context 扱い) |
| `http://<LAN の IP>:8787` | ⚠ **`undefined`** — ⚠ **カメラに触れない** |
| `https://<名前>` | ⚠ **ある** |

⚠ **so スマホから試すには HTTPS が要る。** ⚠ **そして 4G/5G から届くには公開名が要る。**
⚠ **Cloudflare Tunnel は、その 2 つを、ルータに穴を開けずに満たす。**

⚠ **トンネルを通るのは HTTP と WebSocket だけである**
([`adr/0003`](adr/0003-expose-only-http-and-websocket-through-cloudflare-tunnel.md))。
⚠ **メディアはトンネルを通らない。** ⚠ **ブラウザ間を直接流れる**
([`adr/0001`](adr/0001-keep-media-peer-to-peer-and-off-our-servers.md))。
⚠ **つまりこの実験は「トンネルが速いか」を測っているのではない。** ⚠ **NAT を越えられるかを測っている。**

## 2. 用意する

```bash
# cloudflared (Arch なら pacman、他は Cloudflare の配布物)
cloudflared --version
```

⚠ **合言葉トークンの鍵は、その場で作る。** ⚠ **この文書にも `.env.example` にも値は書かない**
([`../.claude/rules/security.md`](../.claude/rules/security.md) § 6)。

```bash
export JOIN_TOKEN_SECRET="$(openssl rand -base64 32)"
```

### 2-1. 使い捨てで済ませる場合(推奨)

⚠ **1 回の実験にはこれで足りる。** ⚠ **ログイン不要、⚠ 後片付けは Ctrl-C だけ。**

```bash
cloudflared tunnel --url http://127.0.0.1:8787
#   → https://<ランダムな名前>.trycloudflare.com が表示される
```

⚠ **表示された URL を、そのまま次で使う。** ⚠ **毎回変わる。**

### 2-2. 名前を固定する場合

```bash
cloudflared tunnel login                     # cert.pem を書く (gitignore 済み)
cloudflared tunnel create kagima-field-test  # 資格情報 JSON を書く (gitignore 済み)
cloudflared tunnel route dns kagima-field-test kagima.<自分のドメイン>
cloudflared tunnel run --url http://127.0.0.1:8787 kagima-field-test
```

⚠ **`cert.pem` と資格情報 JSON は長命の秘密である。** ⚠ **`.gitignore` に入っているが、
⚠ 貼り付け先を間違えないこと。** ⚠ **画面共有中に開かない。**

### 2-3. kagima を起動する

```bash
PUBLIC_BASE_URL="https://<上で出た名前>" \
TRUSTED_SOURCE_HEADER="cf-connecting-ip" \
JOIN_TOKEN_SECRET="$JOIN_TOKEN_SECRET" \
npm run dev
```

⚠ **`PUBLIC_BASE_URL` を間違えると、Host が配る URL が届かない先を指す。**
⚠ **`TRUSTED_SOURCE_HEADER` を省くと、⚠ トンネル越しでは全員が同じ 1 つの発信元に見え、
⚠ 誰か 1 人の失敗が全員の入室制限を使い切る。** ⚠ **起動時の警告がそれを言う。**

## 3. ネットワークの組み合わせ

⚠ **「別のネットワーク」と言えるのは、⚠ 別の NAT の後ろにいるときだけである。**
⚠ **同じ Wi-Fi にいる PC とスマホは、別の端末ではあっても別のネットワークではない。**

| | Host | Guest | ⚠ これで分かること |
|---|---|---|---|
| **A** | 自宅 PC(自宅 Wi-Fi) | スマホ(**Wi-Fi を切って** 4G/5G) | ⚠ **本命。** ⚠ 家庭用 NAT とキャリア NAT のあいだ |
| **B** | 自宅 PC | 同じ Wi-Fi のスマホ | ⚠ **対照。** ⚠ A が失敗したとき、⚠ 失敗が NAT のせいかどうかを分ける |
| **C** | 自宅 PC | 別の場所の回線(テザリング、実家、店) | ⚠ **A の再現性。** ⚠ 1 つの組み合わせは 1 つの組み合わせでしかない |

⚠ **B を飛ばさないこと。** ⚠ **B が失敗したなら、A の失敗は NAT の話ではない。**
⚠ **スマホの Wi-Fi は「オフにする」。** ⚠ **「使っていない」では、つながったままのことがある。**

## 4. 手順

1. ⚠ **PC で kagima を開き、「ルームを作る」を押す。**
2. ⚠ **URL と合言葉を、別々の経路でスマホに渡す**(`PRODUCT.md` § 2)。
   ⚠ **同じチャットに両方を貼ると、⚠ それは実験ではなく、鍵と錠を一緒に送っている。**
3. ⚠ **スマホで URL を開き、合言葉と名前を入れて入室する。**
4. ⚠ **両方の画面に相手が映るまで待つ。**
5. ⚠ **そのまま 30 秒放置する。** ⚠ **見ているのは「つながった瞬間」ではなく「保つかどうか」である。**
6. ⚠ **両方の端末で「診断(実証実験用)」を開き、⚠ 「この観測をコピー」を押して貼り出す。**

⚠ **1 つの組み合わせにつき 3 回。** ⚠ **1 回目だけがうまくいくことも、⚠ 1 回目だけ失敗することもある。**

## 5. 記録する項目

⚠ **診断パネルが出す文面が、そのまま記録である。** ⚠ **手で書き写さない** — ⚠ **写し間違いは、
⚠ 後から見分けがつかない。**

| 項目 | ⚠ なぜ要るのか |
|---|---|
| **verdict** | ⚠ 成功・失敗と、⚠ **失敗ならどの種類か**(下記) |
| **frames decoded** | ⚠ **判定はこれである。** ⚠ `connectionState` ではない |
| **ms to 1st frame** | ⚠ 「つながらない」と「遅い」は別物 |
| **held for** | ⚠ **30 秒保ったか。** ⚠ つながってから落ちるのが、いちばん見落とされる失敗 |
| **local / remote candidates** | ⚠ srflx が出たか = ⚠ **STUN に届いたか** |
| **selected pair** | ⚠ 実際に使われた経路。⚠ `relay` が出たなら TURN が使われている |
| **signalling socket** | ⚠ 切れたか。⚠ **切れても通話は続くはず**([`adr/0010`](adr/0010-a-room-lives-while-somebody-is-in-it-and-not-longer.md)) |
| **transitions** | ⚠ どこまで進んで止まったか |

⚠ **パネルに出ないものも、⚠ 人が書く:**

- ⚠ **いつ、どの組み合わせ(A/B/C)、⚠ 両端の回線(「自宅 Wi-Fi」「4G、キャリア名」)**
- ⚠ **端末とブラウザ**(⚠ **iOS の Safari と Chrome は同じエンジンである** — ⚠ 別物として数えない)
- ⚠ **人が見て何が起きたか**(⚠ 「映ったが音が出ない」は frames では出ない)

### ⚠ 失敗は 3 種類あり、混ぜてはならない

⚠ **これを 1 つに丸めると、⚠ NAT のせいではないものを NAT のせいにする。**

| 診断が言うこと | 何が起きたか | ⚠ TURN で直るか |
|---|---|---|
| **srflx が 1 つも無い** | ⚠ **STUN に届いていない。** ⚠ **NAT より手前の問題** | ⚠ **分からない。** ⚠ TURN の話ではない |
| **srflx はあるが pair が無い** | ⚠ **NAT を越えられなかった** | ⚠ **これが TURN の対象である** |
| **pair はあるが frames が 0** | ⚠ **NAT 以外の問題**(コーデック、権限、送信側) | ⚠ **直らない** |

⚠ **成功の定義は 1 つだけ:** ⚠ **両端で frames が増え、⚠ 30 秒保った。**
⚠ **片側だけ映ったものは成功ではない。** ⚠ **別の行に、片側だけと書く。**

## 6. ⚠ 記録してはならないもの

- ⚠ **IP アドレス。** ⚠ **診断パネルは出さない**(`../src/diagnostics/report.ts`)。
  ⚠ **代わりに SDP や `chrome://webrtc-internals` を貼らないこと** — ⚠ **そちらには全部入っている。**
- ⚠ **合言葉。** ⚠ **画面写真を貼るなら、⚠ 合言葉が写っていないことを確かめてから。**
- ⚠ **ルーム URL。** ⚠ **生きているあいだは、それだけで半分の鍵である。**
- ⚠ **相手の名前、⚠ 映っていたもの。**

⚠ **診断パネルの文面は、そのまま公開の Issue に貼れるように作ってある。**
⚠ **貼れないものを足さないこと。**

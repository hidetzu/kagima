# 0008. Issue の受入基準と `PRODUCT.md` が矛盾したら、`PRODUCT.md` を優先して AI が決める

- 状態: **決定**
- 日付: 2026-09-04
- ⚠ **これは働き方の決定であり、プロダクトの決定ではない**([`0006`](0006-let-the-ai-apply-ready-for-ai-and-gate-on-merge-instead.md) と同じ種類)

## 決定

⚠ **Issue の `Acceptance Criteria` が [`../PRODUCT.md`](../PRODUCT.md) と矛盾した場合、
`PRODUCT.md` を優先する。** ⚠ **AI が決めて実装し、報告する。** ⚠ **止めて訊かない。**

⚠ **これはちょうど 1 組についての規則であり、一般化しない。**

## ⚠ Owner の指示(2026-09-04)

⚠ **以下は Owner の言葉であり、書き換えない。**

> この種の判断は今後 AI が決めてよい
> (Issue の AC と docs/PRODUCT.md が矛盾したら、PRODUCT.md を優先して AI が決め、報告だけする)

## 文脈 — 実際に起きたこと

⚠ **hidetzu/kagima#2 の受入基準 5 はこう書いてあった:**

> ルーム作成 API は共有 URL を返す。合言葉はこの応答に含まない(別経路で渡るため)

⚠ **そのとおりに作ると、Host が合言葉を知る手段が無くなる。**
⚠ **`PRODUCT.md` § 3 の Host 手順 3〜4(合言葉が生成される → 相手に共有する)が成立しない。**

⚠ **矛盾していたのは Owner の判断と実装ではない。** ⚠ **AI が書いた Issue の文と、
Owner が持っているプロダクトの正本である。**

⚠ **これを「人間が決めること」として止めるのは、Owner が書いていない文書の書き損じに
Owner の注意を使わせることになる。**

## ⚠ なぜ 1 組だけなのか

⚠ **この規則の危険は、拡大解釈である。**
⚠ **「矛盾したら AI が優先順位で解決してよい」に読み替えられた瞬間、
Owner の判断を上書きする経路ができる。**

⚠ **だから優先順位そのものは書くが、適用してよいのは 1 組だけだと明記する。**

| 矛盾 | 誰が解決するか |
|---|---|
| ⚠ **Issue の `Acceptance Criteria` と `PRODUCT.md`** | ⚠ **AI。`PRODUCT.md` に従って作り、報告する** |
| Issue の `Owner Decisions` と何か | ⚠ **Owner。** ⚠ **`Owner Decisions` は決して上書きしない** |
| `PRODUCT.md` と ADR | ⚠ **Owner** |
| ADR とコード | ⚠ **Owner** |
| `docs/SPEC.md` とコード | ⚠ **Owner** |

⚠ **順序を知っていることは、適用してよいことを意味しない。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **すべての矛盾を優先順位で AI が解決する** | ⚠ **Owner の判断を上書きする経路ができる。** ⚠ **`Owner Decisions` は上書きされてはならない** |
| **従来どおり全部止めて訊く** | ⚠ **AI が書いた文の書き損じで Owner を止めることになる。** ⚠ **`PRODUCT.md` § 7 が「やりとりの回数を増やして解決しない」と言っている** |
| **AI が Issue の受入基準を書き換えて辻褄を合わせる** | ⚠ **矛盾していた証拠が消える。** ⚠ **あとから読む人には、最初からそう書いてあったように見える** |
| **黙って `PRODUCT.md` に従い、報告しない** | ⚠ **同上。** ⚠ **解決したことが読めないなら、解決していないのと変わらない** |

## ⚠ 越えてはならない境界

```text
Owner Decisions は、この規則では絶対に上書きしない
Issue の受入基準を、作ったものに合わせて書き換えない
  ⚠ 訂正案は出す。⚠ 書き換えるのは Owner である
この規則を根拠にスコープを広げない
  ⚠ 矛盾を解くのであって、PRODUCT.md が許しているだけの作業を始めてよいわけではない
完了報告と PR に、⚠ どの基準が、⚠ PRODUCT.md の何と、⚠ 何を作ったかを書く
```

## ⚠ しないと決めた主張

- ⚠ **「AI が仕様を決められるようになった」とは言わない。**
  ⚠ **決めているのは「2 つの文書のどちらに従うか」だけであり、⚠ どちらも Owner のものである。**
- ⚠ **「Owner の確認が減った」とも、まだ言わない。**
  ⚠ **減ったかどうかは、この規則が何回発動したかを見なければ分からない。**
  ⚠ **いまのところ発動は hidetzu/kagima#2 の 1 回である。**

## 影響

- ⚠ **`.claude/rules/owner-decisions.md` と `.claude/skills/issue-ready/SKILL.md` が
  上流テンプレートからさらに乖離した**([`0006`](0006-let-the-ai-apply-ready-for-ai-and-gate-on-merge-instead.md) の 4 ファイルのうち 2 つ)。
- ⚠ **`issue-ready` 第 8 項は、この 1 組では発動しなくなった。**
  ⚠ **ただし判定には「2 つが食い違っている」と書く。** ⚠ **解決できることと、
  書かなくてよいことは別である。**
- ⚠ **hidetzu/kagima#2 の受入基準 5 は、いまも矛盾したまま残っている。**
  ⚠ **書き換えないのが規則だからである。** ⚠ **訂正案は Issue のコメントにある。**

# 0005. ルームの状態はプロセスのメモリだけに置き、永続化しない

- 状態: **決定**
- 日付: 2026-09-04

## 決定

⚠ **ルーム、合言葉、参加者、signaling の途中状態は、動いているプロセスのメモリにだけ置く。**
⚠ **データベースを持たない。** ⚠ **ディスクに書かない。** ⚠ **外部のキャッシュも使わない。**

⚠ **プロセスが終われば、動いていたルームは全部なくなる。** ⚠ **これは仕様である。**

## 文脈

- ⚠ **`PRODUCT.md` § 1 が「残らないこと」を売りだと言っている。**
  ⚠ **永続化層は、残さない約束を運用の努力目標に変える。**
- ⚠ **持たないものは漏れない。** ⚠ **バックアップからも、スナップショットからも、
  ログ収集基盤からも漏れない。** ⚠ **これは注意深さではなく構造で得られる性質である。**
- ⚠ **v0.1.0 に永続ルームは非目標として明記されている**([`../PRODUCT.md`](../PRODUCT.md) § 4)。

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **SQLite に置く**(軽いから) | ⚠ **軽さは論点ではない。** ⚠ **ファイルができた時点で、消える保証が運用の話になる** |
| **Redis に置く**(TTL が使えるから) | ⚠ **TTL は消える保証ではない。** ⚠ **依存も増える** |
| **合言葉だけハッシュして保存する** | ⚠ **保存しない、が約束である。** ⚠ **ハッシュでも保存は保存である** |
| **再起動時にルームを復元する** | ⚠ **復元できるということは、どこかに残っていたということである** |
| **将来の永続ルームに備えて層だけ作る** | ⚠ **非目標のために構造を複雑にしない**(`PRODUCT.md` § 2) |

## ⚠ 越えてはならない境界

```text
プロセスの外に、ルームの状態を出さない
ルームを閉じたら、保持していたものを落とす
  ⚠ 何を落とすのかを個別に言う(合言葉 / Token / 参加者 / signaling のバッファ)
閉じたルームは、存在しなかったルームと同じ応答を返す(0004)
「デバッグのために」記録を残さない
```

⚠ **これらを変えることは Owner 判断である**([`../PRODUCT.md`](../PRODUCT.md) § 6)。

## ⚠ しないと決めた主張

- ⚠ **「会話の内容はどこにも残らない」とは言わない。**
  ⚠ **言えるのは「我々のプロセスは受け取らないし、持たない」までである**
  ([`0001`](0001-keep-media-peer-to-peer-and-off-our-servers.md))。
- ⚠ **「メモリから消えた」とも言わない。**
  ⚠ **参照を落としたことと、メモリ上に残っていないことは別の主張である**
  ([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md) —
  ⚠ **ディスクに書いていない ≠ 保持していない**)。
  ⚠ **後者を主張するなら、それを示す検査が要る。**

## 影響

- ⚠ **プロセスの再起動 = 全ルーム終了である。** ⚠ **デプロイがそのまま切断になる。**
  ⚠ **これを緩める案は、全部この ADR に触れる。**
- ⚠ **プロセスは 1 つである**([`0002`](0002-serve-web-and-signaling-from-one-typescript-process.md))。
  ⚠ **増やすなら、状態の置き場所を先に決め直すことになる。**
- ⚠ **放置されたルームの回収が必要になる。** ⚠ **その条件はまだ決めていない**
  ([`../DISCOVERY.md`](../DISCOVERY.md) § 5)。

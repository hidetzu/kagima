# 0031. ⚠ 発行する人に 1 日の枠を与える。⚠ 主体が続くからそれができる

- 状態: **決定**
- 日付: 2026-09-08
- 対象: ⚠ [`0030`](0030-let-the-host-sign-in-with-google-and-keep-the-guest-anonymous.md)
  の続き。⚠ **[`0022`](0022-start-on-cloudflares-free-tier-with-one-durable-object-per-room.md)
  の境界に 方針を載せる。** ⚠ **[`0023`](0023-write-the-minimum-so-a-room-outlives-its-sockets.md)
  の「4 フィールド」が 5 になる**

## ⚠⚠ 文脈 — ⚠ 費用が先ではない

⚠ **[`../DISCOVERY.md`](../DISCOVERY.md) § 9 の 仮説 D**(Owner 判断 2026-09-08):

> ⚠ **「誰でも匿名で部屋を量産できる」のではない。**
> ⚠ **発行する側にだけ 続く主体性を求め、⚠ 招待された側にはアカウントを作らせない。**

⚠ **[`0030`](0030-let-the-host-sign-in-with-google-and-keep-the-guest-anonymous.md) が
「発行する側は名乗る」を作った。** ⚠⚠ **枠は その続きである** — ⚠ **主体が続くから、
⚠ その主体に 予算を割り当てられる。** ⚠ **匿名の発行者には 割り当てようがない。**

⚠ **Free 枠に収めることは 同じ実装で満たされるが、⚠ 順序は これである。**
⚠ **逆に書くと、⚠ 運用の都合を製品の売りとして語ることになる**
([`../DISCOVERY.md`](../DISCOVERY.md) § 9 が その反証を先に書いている)。

## ⚠ 公式の値(⚠ 出所と参照日)

⚠ **Cloudflare Durable Objects Pricing、⚠ 参照日 2026-09-08。**

```text
Free    Requests 100,000 / day     Duration 13,000 GB-s / day
        ⚠⚠ Daily free limits reset at 00:00 UTC
        ⚠ 超えると その種類の operation が失敗する
        ⚠ idle で hibernation の条件を満たすものは duration を課金されない
```

## 決定

| | 値 | ⚠ 何を守るか |
|---|---|---|
| ⚠ **サービス全体** | ⚠ **20 room-hours / UTC day** | ⚠ Free の 28.21 room-hours の 70.9% |
| ⚠ **発行する人ごと** | ⚠ **60 room-minutes / UTC day** | ⚠ **量産させない**(仮説 D) |
| ⚠⚠ **同時に開いている部屋** | ⚠⚠ **8** | ⚠ **下記「soft な上限」** |

⚠ **どれかに達したら 新規作成だけを止める。** ⚠⚠ **開いている部屋は 途中で切らない。**

### ⚠ 単位は requests ではなく、⚠ 部屋の active wall-clock

⚠ **`socketOpenMs`** — ⚠ **1 本以上 socket が開いていた 部屋の wall-clock**
([`0022`](0022-start-on-cloudflares-free-tier-with-one-durable-object-per-room.md))。
⚠ **部屋ごとであって socket の合計ではない** — ⚠ **2 人 30 分は 30 分である。**

⚠⚠ **so 再接続も 再 join も 二重に数えない。** ⚠ **単位がもともと そうなっている。**

⚠ **`socketOpenMs` は 課金される duration の 下限 である**(同 ADR)。⚠ **枠はその下限に対して
かけるので、⚠ 実際の消費は これより少し多い。** ⚠ **余白がそれを吸う(下記)。**

### ⚠ 20 h が妥当である根拠、⚠ と 何が妥当でないか

```text
1 room-hour = 3600s × 0.128GB = 460.8 GB-s
天井        = 13,000 / 460.8  = 28.21 room-hours/day
20 h        = 9,216 GB-s      = 天井の 70.9%
⚠ 余白      = 8.21 room-hours = 29.1%
```

⚠ **余白が吸うもの:**

| | ⚠ 見積もり |
|---|---|
| ⚠ 最初の socket の前 / 最後の socket の後 | ⚠ 実測 2026-09-05: **8 秒生存 / 15 秒消滅**。⚠ 40 room/day で ≈ **0.17 room-hours** |
| ⚠ alarm の起床([`0025`](0025-let-a-room-let-go-of-itself.md)) | ⚠ ミリ秒 |
| ⚠ 台帳オブジェクト自身 | ⚠ 1 日 1,200 回起こしても ≈ 3 GB-s |
| ⚠⚠ **Cloudflare の数え方と我々の数え方の差** | ⚠⚠ **測っていない** |

⚠⚠ **余白の大半は 最後の行のためである。** ⚠ **既知の overhead は 0.2 room-hours 程度で、
⚠ 残る 8 h は「知らないこと」に置いてある。** ⚠ **そう書く。**

### ⚠⚠ 上限は soft である。⚠ だから同時数を縛る

⚠ **「開いている部屋を切らない」と決めた以上、⚠ 上限に達した後も 既存の部屋は伸びる。**

```text
⚠ 超過の上限 = 同時に開いている部屋数 × 各部屋の残り個人枠
⚠ 個人枠は 1 h なので、⚠ N 部屋なら 最大 N 時間 伸びる
⚠ 20 + 8 = 28 ≦ 28.21     ⚠⚠ so N ≦ 8
```

⚠ **同時 8 部屋は、⚠ 選んだ値ではなく 上の式から出る値である。**
⚠ **`1 Host = 1 active room` なので、⚠ 同時 8 人までと同じことである。**

### 保存先 — ⚠ Durable Object を 1 つ

| 案 | ⚠ 判断 |
|---|---|
| ⚠ **DO 1 つ(台帳)** | ⚠⚠ **採る。** ⚠ 直列実行が保証され、⚠ 読んで足して書くのが原子的 |
| KV | ⚠⚠ **不可。** ⚠ 結果整合であり、⚠ quota には使えない |
| D1 | ⚠ 2 種類目の保存を持ち込む。⚠ 台帳 1 つで足りるうちは要らない |

⚠⚠ **これは kagima で初めて「1 つの部屋より長生きするもの」である。**
⚠ **`CLAUDE.md` § 3 の「プロセスを越えて残るもの」であり、⚠ この ADR がその許可である。**

### ⚠ 台帳が持つもの — ⚠ これで全部

```text
day        ⚠ 数えている UTC の日付      ⚠ 日付が変われば 全部捨てて 0 から
usedMs     ⚠ サービス全体の その日の合計
openRooms  ⚠ いま開いている部屋の数
perHost    ⚠ hash(アカウント) → ms      ⚠⚠ アドレスは持たない
perRoom    ⚠ roomId → 最後に受け取った累計   ⚠ 再送で二重に足さないため
```

⚠ **アカウントは 署名鍵での HMAC で持つ。** ⚠⚠ **台帳にメールアドレスは 1 文字も入らない。**
⚠ **鍵は この配置のものなので、⚠ その hash は 他所では何も意味しない。**
⚠ **日をまたげば 全部消える** — ⚠ **so「その人が何をしたか」は 1 日より長く残らない**
([`../PRODUCT.md`](../PRODUCT.md) § 5)。

⚠ **`perRoom` の行は、⚠ 部屋が最後の報告をしたときに消す。**

### ⚠ 二重に数えない方法

⚠ **部屋は 累計 を送り、⚠ 台帳が `累計 − 前回` を足す。** ⚠ **再送は 0 を足す** — ⚠ **冪等。**

⚠⚠ **部屋が evict されて戻ると、⚠ その部屋の時計は 0 から始まる。**
⚠ **so 累計を部屋の storage に持つ** — ⚠ **[`0023`](0023-write-the-minimum-so-a-room-outlives-its-sockets.md)
の「4 フィールド」が 5 になる**(Owner 判断 2026-09-08)。
⚠ **足すのは 数字 1 つ(ミリ秒)であり、⚠ 誰についての情報でもない。**

### ⚠ 台帳に届かなかったら 断る

⚠ **fail closed**(Owner 判断 2026-09-08)。⚠ **費用を守る側に倒す。**
⚠ **台帳 1 つが サービス全体の単一障害点になる** — ⚠ **が、⚠ 上限を超えれば 扉ごと応じなく
なるので**([`0022`](0022-start-on-cloudflares-free-tier-with-one-durable-object-per-room.md))、
⚠ **どちらに転んでも止まるなら 費用を守るほうを選ぶ。**
⚠ **届かなかった回数は 数える**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。

### ⚠ 人が読む文言は 2 つ

⚠ **Owner 判断 2026-09-08。**

```text
⚠ 個人の枠を使い切った      今日の分を使い切りました。明日またルームを作れます。
⚠ 全体が満杯 / 同時数が上限  いま新しいルームを作れません。しばらくしてからお試しください。
```

⚠ **3 つを 1 文にはしない** — ⚠ **枠を使い切っていない人に「使い切りました」と言うのは
嘘であり、⚠ その人の次の一手が変わる**(`CLAUDE.md` § 4-1)。
⚠ **全体と同時数は 分けない** — ⚠ **どちらも「しばらく待つ」であり、⚠ 分ければ サービスの
混み具合を外に出すことになる。**

⚠⚠ **どれも Guest には出ない。** ⚠ **止まるのは 作成だけである。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| ⚠ **requests で数える** | ⚠ **効くのは duration のほうである**([`0022`](0022-start-on-cloudflares-free-tier-with-one-durable-object-per-room.md))。⚠ **`0028` で polling が消えて以降、⚠ requests は桁違いに余っている** |
| ⚠ **KV に持つ** | ⚠ **結果整合。** ⚠ **quota は 数えた瞬間に正しくなければ意味がない** |
| ⚠ **Guest も数える** | ⚠⚠ **識別することになる**(`../PRODUCT.md` § 5)。⚠ **仮説 D の片側が消える** |
| ⚠ **上限で 開いている部屋を切る** | ⚠ **通話中の人を 費用の都合で切ることになる。** ⚠ **Owner 指定** |
| ⚠ **同時数を縛らない** | ⚠ **soft な上限の超過が 部屋数に比例して伸びる。** ⚠ **8 を超えると 最悪 Free を超えうる** |
| ⚠ **台帳が落ちたら通す** | ⚠ **上限が効かない窓ができる。** ⚠ **その間に Free を使い切られうる** |

## ⚠ 越えてはならない境界

```text
⚠ Guest は数えない、⚠ 識別しない
⚠ 台帳にアドレスを入れない            ⚠ hash だけ
⚠ 日をまたいで 何も残さない
⚠ 上限に達しても 開いている部屋を切らない
⚠ 報告は累計。⚠ 差分を送らない        ⚠ 再送で二重に数える
⚠ 文言は 2 つ。⚠ Guest には出ない
⚠ 部屋の storage に足すのは 数字 1 つ  ⚠ 誰についての情報も足さない
```

## ⚠ しないと決めた主張

- ⚠ **「Free を超えない」とは言わない。** ⚠ **言えるのは「20 + 8 ≦ 28.21 なので、⚠ この式が
  成り立つ限り超えない」までである。** ⚠ **式の前提(`socketOpenMs` が下限であること)は
  測っていない。**
- ⚠ **「量産されない」が 利用者の価値だとは言わない。**
  ⚠ **[`../DISCOVERY.md`](../DISCOVERY.md) § 9 が、⚠ それを反証条件として先に書いている。**
- ⚠ **60 分 と 8 部屋 が 正しいとは言わない。** ⚠ **60 分は選んだ値、⚠ 8 は式から出た値である。**

## ⚠ 実装したときに ずれたところ(⚠ 2026-09-09)

⚠ **決めたことは動いていない。** ⚠ **形が 4 か所 変わった。** ⚠ **書いておく。**

| ⚠ ADR の記述 | ⚠ 実際 | ⚠ なぜ |
|---|---|---|
| ⚠ 台帳が `openRooms` を持つ | ⚠⚠ **持たない。** ⚠ **`perRoom` の行数を数える** | ⚠ **1 つの問いに 2 か所が答えると ずれる**(`CLAUDE.md` § 3)。⚠ **ずれるのは 上限を読む側である** |
| ⚠ `perRoom` は `roomId → 累計` | ⚠ **`roomId → { 発行者の hash, 累計 }`** | ⚠ **報告は「どれだけ」であって「誰の」ではない。** ⚠ **部屋は 誰がサインインしたかを知らないし、⚠ 知ってはならない** |
| ⚠ 「4 フィールドが 5 になる」 | ⚠ **部屋の storage に 別のキーを 1 つ** | ⚠ **`Room` は platform-free であり、⚠ Durable Object が何秒起きていたかは Node の部屋には要らない** |
| ⚠ 台帳への報告 | ⚠ **60 秒に 1 回まで。⚠ span が終わるときは 必ず** | ⚠ **heartbeat は 20 秒。** ⚠ **時間単位の上限に 毎分 3 回は要らず、⚠ ADR 自身の見積もり(1 日 1,200 回)に合う** |

### ⚠⚠ 名乗る仕組みが無い配置には、⚠ 枠も無い

⚠ **枠が置けるのは 発行する側が続く主体だからである**(この ADR の冒頭)。
⚠⚠ **so サインインが設定されていない配置には 主体が無く、⚠ 割り当てる相手も無い。**
⚠ **その配置は 扉も無い**(`src/worker.ts` の `gateSecret` — ⚠ **同じ 2 つの変数で決まる**)。
⚠ **`wrangler dev --local` に何も渡さない場合が それであり、⚠ deploy は常に両方を持つ**
([`../DEPLOY.md`](../DEPLOY.md))。
⚠ **[`../SPEC.md`](../SPEC.md) に、⚠ どの配置で 何が言えるかを書いた。**

### ⚠ 検査が届いたところ、⚠ 届いていないところ

```text
⚠ 同時に開ける部屋の上限   ⚠ 届いた。⚠ npm run worker のケース the-day
                          ⚠ 本物の Durable Object 8 部屋 + 1 で断られ、⚠ 1 つ閉じると また作れる
⚠ 60 room-minutes         ⚠ 届いていない。⚠ 算術としてのみ (test/ledger.test.ts)
⚠ 20 room-hours           ⚠ 届いていない。⚠ 同上
```

⚠⚠ **後の 2 つは 時間そのものが要る。** ⚠ **台帳に値を差し込む口を作れば検査できるが、
⚠ それは 入口を 1 つ増やすことである** — ⚠ **作らない。**
⚠ **「検査していない」と書くほうを採る**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。

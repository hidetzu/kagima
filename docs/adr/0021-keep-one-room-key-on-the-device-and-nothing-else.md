# 0021. 端末に置くのは、⚠ ルーム 1 つ分の鍵だけ

- 状態: **決定**
- 日付: 2026-09-06
- 決めた人: **Owner**
- 片付ける課題: [kagima#75](https://github.com/hidetzu/kagima/issues/75)

## 文脈

⚠ **実測(2026-09-06、⚠ 実機、⚠ Android の Chrome):**

```text
13:18:02  ⚠ Host が繋がった
13:19:14  ⚠ socket が落ちた {"heldMs":72655}
          ⚠ 影のハートビートが「切っていたはず」と言った回数: 0
13:30     ⚠ 戻ると、⚠⚠ 画面は「ルームを作る」
```

⚠ **ブラウザが背面のタブを破棄し、⚠ 復帰時に最初から読み直した。**
⚠ **`hostKey` はページの変数にしか無く、⚠ ページと一緒に消えた。**

```text
⚠ ルームはサーバに ROOM_IDLE_MS のあいだ生きている
⚠⚠ だが Host はもう入れない
⚠⚠ 既に渡した URL でノックされても、⚠ 誰にも届かない (0018)
```

⚠ **[`0018`](0018-give-the-host-a-short-lived-role-inside-one-room.md) が戻る経路を作り、
⚠ [`0019`](0019-let-the-host-come-back-on-its-own.md) が自動再接続を入れた。**
⚠⚠ **どちらも ページが生きていること を前提にしていた。**

⚠ **そしてこれは kagima の一番大事な瞬間に起きる** — ⚠ **URL を渡しに別アプリへ行っている
あいだであり、⚠ [`0017`](0017-let-the-host-decide-who-comes-in-instead-of-a-passphrase.md)
が「Host はどのみちその場に居た」と書いた、まさにその時間である。**

## 決定

⚠ **`localStorage` に、⚠ `roomId` と `hostKey` を 1 組だけ 置く。**
⚠ **消えるのは、⚠ 我々が消すときだけである。**

```text
書く      ⚠ ルームを作った直後(⚠ socket より先。⚠ 作れて覚えていない状態を作らない)
読む      ⚠ ページが起動したとき。⚠ host-session を叩いて、⚠ 通れば戻る
消す      ⚠ ルームを閉じたとき
          ⚠ host-session が拒まれたとき(⚠ もう無い部屋の鍵を持ち続けない)
          ⚠ 4005 を受けたとき(⚠ ルームが終わった)
```

### ⚠⚠ 1 つだけ、⚠ 置き換える

⚠ **追記しない。** ⚠ **`localStorage` の鍵は 1 つ**(`kagima.room`)。

⚠ **理由は下の § 約束 に書く。** ⚠ **溜めれば、⚠ それは「この端末が過去に作ったルームの数」に
なる。**

### ⚠ 書かないもの

```text
join token   ⚠ 短命であることが security.md § 4 の要点である。⚠ 書けば取り去ることになる
ニックネーム  ⚠ ノックした人のものであって、⚠ Host のものではない (PRODUCT.md § 5)
共有 URL     ⚠ roomId から導ける。⚠ 覚えると、⚠ 住所が変わった瞬間に古くなる
```

## ⚠⚠ 約束との関係 — ⚠ 1 行ずつ当てた

⚠ **[`../PRODUCT.md`](../PRODUCT.md) § 5:**

| 約束 | ⚠ 触るか |
|---|---|
| 録画しない / 文字起こししない | ⚠ 触らない |
| 映像と音声を我々のサーバに保存しない | ⚠ 触らない |
| ⚠ **誰がノックしたかを記録に残さない** | ⚠ **触らない** — ⚠ **残すのは Host 自身の鍵であって、⚠ 来訪者ではない** |
| ルームが閉じたあと会話の内容は残らない | ⚠ 触らない |
| ⚠⚠ **アカウントを作らせない。⚠ 利用者を継続的に識別する手段を持たない** | ⚠⚠ **ここだけ** |
| 入れなかった人にルームの存在を教えない | ⚠ 触らない |
| カメラは入れると決まってから | ⚠ 触らない |

### ⚠ 「継続的に識別する手段を持たない」との関係

⚠ **`hostKey` は 1 つのルームに紐づく。** ⚠ **ルームが終われば何も開けない。**
⚠ **so これは 利用者 の識別子ではなく、⚠ 部屋 の鍵である。**

⚠⚠ **ただし 溜まれば別である。** ⚠ **鍵が並べば、⚠ それは「この端末は過去にこれだけルームを
作った」という記録になり、⚠ 継続的な識別に近づく。**

⚠ **so 「1 つだけ」は便宜ではなく、⚠ 約束を守るための条件である。**
⚠ **壁は `test/remember.test.ts`「⚠⚠ it never becomes a pile」。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **`sessionStorage`** | ⚠ **破棄からの復帰で残るかを 測っていない。** ⚠ **測っていないものに賭ける形になる** |
| **URL に載せる** | ⚠⚠ **`security.md` § 2 が禁じている形そのもの。** ⚠ **URL は履歴にも referer にも残る** |
| **何もしない** | ⚠ **kagima の一番大事な瞬間が壊れたままになる** |
| **鍵をルームごとに分けて持つ** | ⚠⚠ **溜まる。** ⚠ **約束に触れる**(上記) |
| **join token も一緒に置く** | ⚠ **短命さを取り去る**(`security.md` § 4)。⚠ **`host-session` で取り直せばよい** |

## ⚠ 越えてはならない境界

```text
1 つだけ。⚠ 追記しない
join token を書かない
来訪者のものを書かない
死んだ鍵を持ち続けない  ⚠ 閉じたとき / 拒まれたとき / 4005 のとき に消す
Guest 側には置かない    ⚠ Guest が持つのは Host の判断であって、⚠ 鍵ではない
```

## ⚠ しないと決めた主張

- ⚠ **「これで Host は必ず戻れる」とは言わない。**
  ⚠ **端末が鍵を保てないことはある**(⚠ プライベートウィンドウ、⚠ サイトデータの拒否)。
  ⚠ **そのとき kagima は動くが、⚠ この便宜だけを失う。**
- ⚠⚠ **「破棄されたのは画面消灯のせいである」とは言わない。**
  ⚠ **Owner の推測であり、⚠ まだ測っていない**([kagima#75](https://github.com/hidetzu/kagima/issues/75)
  に、⚠ 画面点灯のまま別アプリ と 画面消灯 を分けて測る手順がある)。
- ⚠ **[kagima#62](https://github.com/hidetzu/kagima/issues/62) は この実測では測れなかった。**
  ⚠ **影が 0 回だったのは「答え続けた」ではなく、⚠ 「判断する前に socket が無くなった」である。**

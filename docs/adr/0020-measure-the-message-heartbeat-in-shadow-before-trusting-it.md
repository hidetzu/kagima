# 0020. メッセージ版ハートビートは、⚠ 影で測ってから信じる

- 状態: **決定**(⚠ **期限つき**。⚠ 終わり方は下記)
- 日付: 2026-09-06
- 決めた人: **Owner**
- 片付ける課題: [kagima#62](https://github.com/hidetzu/kagima/issues/62)

## 文脈

⚠ **Worker のサーバ側 WebSocket に `ping` は無い**(⚠ 実測 2026-09-06、
[`0015`](0015-put-the-service-on-cloudflare-after-three-things-are-settled.md))。
⚠ **so ハートビートは、⚠ 両方のプラットフォームが持つもの — ⚠ テキストのメッセージ — に
移さねばならない。**

⚠⚠ **だが 移すと、⚠ 測っているものが変わる。**

```text
いま    ⚠ pong を返すのは ブラウザ       ⚠ 測っているのは「TCP とブラウザが生きている」
移すと  ⚠ pong を返すのは ページの JS    ⚠ 測れるのは「ページが生きて動いている」
```

⚠ **強い方向に変わる。** ⚠⚠ **そして socket を いまより多く 切る方向にも変わる。**
⚠ **どれだけ多いかは、⚠ 誰も測っていない。**

⚠ **背面に回ったページで何が起きるかは、⚠ kagima では 1 度も測られていない**
([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。
⚠ **仕様に `freeze` / `resume` が在ることは分かるが、⚠ 条件も時間も実装依存である。**

## 決定

⚠ **メッセージ版のハートビートを 実装する。** ⚠⚠ **ただし、⚠ 何も決めさせない。**

```text
サーバ  ⚠ 拍ごとに {"type":"ping","n":N} を送る
ページ  ⚠ {"type":"pong","n":N} を返す(⚠ transport が返す。⚠ ページは見ない)
サーバ  ⚠ 所定回数 valid pong が返らなければ 「切っていたはず」と 記録する
        ⚠⚠ 切らない。⚠ 切るのは いまも protocol ping である
```

⚠ **so 実使用のまま、⚠ 実機で、⚠ 誰も切られずに測れる。**

### ⚠⚠ `n` が「valid」を意味あるものにする

⚠ **`n` が無ければ、⚠ ページは 受け取っていない ping にも pong を返せる。**
⚠ **そのとき心拍は「動いている」と言うが、⚠ そのページは何も受け取っていない。**
⚠ **番号を返させれば、⚠ 答えは「これがここに届いた」になる** — ⚠ **測りたいのはそれである。**

⚠ **いま待っている番号だけが数を戻す。** ⚠ **古い番号の echo は「ページが遅れている」であって
「いま居る」ではない。**

### ⚠ ページの生死そのものも記録する

⚠ **`visibilitychange` と `freeze` / `resume`。** ⚠ **`docs/adr/0012` の語彙の外へ出ない** —
⚠ **時刻(ページ読み込みからの ms)と、⚠ 閉じた語の集合だけである。**

⚠⚠ **`freeze` を報告しないブラウザでは、⚠「凍らなかった」ではなく「このブラウザは言わない」と
書く。** ⚠ **観測されなかったこと ≠ 起きなかったこと。**

## ⚠ 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **先に本体を入れ、値は据置で調整** | ⚠⚠ **「いまより多く切る」変更を、⚠ どれだけ多いか分からないまま入れることになる** |
| **計器だけ入れて、⚠ ハートビートは入れない** | ⚠ **測れるのは「ページが背面に回った」までで、⚠ 「そのとき pong が止まったか」は測れない。** ⚠ **知りたいのは後者である** |
| **クライアント発の片道にする** | ⚠ **間隔と部屋の寿命をクライアントが握る**(kagima#62 で比較済み) |
| **`n` を付けない** | ⚠ **「valid pong」が意味を失う。** ⚠ **受け取っていないページも答えられる** |

## ⚠⚠ 終わり方 — ⚠ 始める前に書く

⚠ **`CLAUDE.md` § 3 は「同じ問いに答える実装を 2 つ持たない」と定めている。**
⚠ **これは 意図的に 2 つであり、⚠ 測るあいだだけである。**
⚠ **[`0011`](0011-turn-on-a-field-test-mode-that-costs-two-promises-on-purpose.md) が同じ形を
取り、⚠ [`0014`](0014-retire-the-field-test-mode-now-that-kagima-16-is-closed.md) が閉じた。**

⚠ **終わらせる条件: ⚠ [kagima#62](https://github.com/hidetzu/kagima/issues/62) の実機計測が
出て、⚠ 値が決まったとき。**

⚠ **終わらせる PR がすること:**

```text
⚠ protocol ping を消す(⚠ socket.ping / onPong / ws.on("pong") / SignalingSocket の 2 つ)
⚠ 影の記録を、⚠ 実際に切る判断に変える
⚠ 0009 を同時に更新する         ⚠ ws に求めるものが 1 つ減る。⚠ 後回しにしない(Owner)
⚠ 消えたものの一覧を置き、⚠ `docs-check` が不在を機械で押さえる
```

⚠ **その一覧はこの ADR には まだ 無い。** ⚠ **いま消すものが何も無いからである** —
⚠ **不在を押さえる検査は、⚠ 終わらせる PR で初めて効く。**

⚠ **`docs-check` はその目印を ADR の本文から探す。** ⚠ **so ここでその語を書くと、⚠ 「この ADR は
もう何かを退役させた」と読まれる** — ⚠ **実際、⚠ 最初はそう書いて落ちた。**

## ⚠ しないと決めた主張

- ⚠ **「背面のタブでハートビートが止まる」とは言わない。** ⚠ **測っていない。**
  ⚠ **測るために これ が在る。**
- ⚠ **「protocol ping より良い」とも言わない。** ⚠ **測っているものが違う。**
  ⚠ **強い方向に違うが、⚠ 切りすぎる方向にも違う。**
- ⚠ **「死んだ接続を確実に外せる」とは言わない**(⚠ Owner が条件から「確実」を外した)。
  ⚠ **言えるのは「送ったハートビートに対して所定回数 valid pong が返らなければ `CLOSE_SILENT`」
  までである。**

## 影響

- ⚠ **利用者から見た振る舞いは 1 つも変わらない。** ⚠ **切られ方も、文言も、同じである。**
- ⚠ **フレームが 1 拍あたり 2 本増える**(⚠ ping と pong)。
  ⚠ **Durable Object は接続中ずっと起きているので、⚠ duration は変わらない**
  ([`0015`](0015-put-the-service-on-cloudflare-after-three-things-are-settled.md))。
  ⚠ **課金規則そのものは測っていない**(kagima#47)。
- ⚠ **診断パネルに 4 行増える。** ⚠ **Owner が実機で読んで写せる。**

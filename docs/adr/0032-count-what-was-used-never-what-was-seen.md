# 0032. ⚠ 機能が使われたかを数える。⚠ 何を見たかは 決して測らない

- 状態: **決定**
- 日付: 2026-09-09
- 対象: ⚠ **[`0014`](0014-retire-the-field-test-mode-now-that-kagima-16-is-closed.md)
  が「また要るなら、⚠ そのとき改めて ADR を書く」と書いた、⚠ その ADR である**

## 文脈

⚠ **[`../PRODUCT.md`](../PRODUCT.md) § 1 が 2026-09-09 に定まった**(⚠ Owner 決定):

> ⚠ **誰かと 5〜20 分だけ、⚠ 同じものを見て「ここ」と言える一時ルーム**

⚠ **v0.1.0 に 画面共有 と ポインタ が入る。** ⚠⚠ **so「同じものを見る」が 使われているかどうかを
知らないまま、⚠ 次に何を作るかは決められない。**

⚠ **kagima は 一度 集める仕組みを持ち、⚠ 捨てている**
([`0011`](0011-turn-on-a-field-test-mode-that-costs-two-promises-on-purpose.md)、
[`0014`](0014-retire-the-field-test-mode-now-that-kagima-16-is-closed.md))。
⚠ **あれは 2 つの約束を意図的に代償にする仕組みで、⚠ 役目が終わったので消した。**
⚠⚠ **今度は 約束を 1 つも代償にしない。** ⚠ **それが この ADR の制約である。**

## ⚠⚠ 決定 1 — ⚠ Host を 日をまたいで識別しない

⚠ **Owner 判断 2026-09-09。**

⚠ **草案には「Host の再利用率」「同じ Host が繰り返し使う」があった。**
⚠⚠ **どちらも「同じ人が 別の日に戻ってきた」と分かる必要がある。**

⚠ **それは [`../PRODUCT.md`](../PRODUCT.md) § 5 と
[`0031`](0031-give-the-issuer-a-daily-budget-because-the-issuer-is-a-continuing-subject.md)
に 正面からぶつかる:**

> ⚠ **その日にどれだけ使ったかは数える。** ⚠ **1 日で消える。**
> ⚠ **その人が何をしたかの記録は持たない。**

⚠⚠ **so 指標のほうを落とす。** ⚠ **「Host 再利用率」は 測らない。**
⚠ **計測のために Privacy の約束を弱めない** — ⚠ **これが順序である。**

## 決定 2 — ⚠ 数えるのは ルーム単位・その日ぶん

| 数えるもの | ⚠ 何を判断するため |
|---|---|
| 作られたルーム数 | ⚠ 分母 |
| ⚠ Guest が入室まで到達した割合 | ⚠ 入口が成立しているか(⚠ E1 と同じ問い) |
| ルーム継続時間 | ⚠ 「5〜20 分」が実際そうなのか |
| camera on / off、⚠ mute | ⚠ **「顔を見る」が本当に要るのか** |
| ⚠ 画面共有を開始したルームの割合 | ⚠⚠ **「同じものを見る」仮説の本体** |
| 画面共有開始までの時間 | ⚠ そこへ至る摩擦 |
| ⚠ ポインタを使ったルームの割合、⚠ 利用回数 | ⚠⚠ **「ここ」と言えることの本体** |
| 画面共有中の滞在時間 | ⚠ 見ている時間と 話している時間は別か |
| 正常終了 / 途中離脱 | ⚠ どこで切れるか |

⚠ **ファネル:**

```text
ルーム作成  →  通話開始  →  画面共有  →  ポインタ利用
```

⚠⚠ **どの数も ルームについてであって、⚠ 人についてではない。**
⚠ **`hash(アカウント)` にも結び付けない** — ⚠ **`0031` の台帳が持つ hash は 枠のためだけであり、
⚠ 計測はそこを見ない。**

## 決定 3 — ⚠ 決して測らないもの

```text
⚠ 映像            ⚠ 音声          ⚠ 共有された画面
⚠ ポインタが指した内容             ⚠ 会話の内容
⚠ Guest が何を見せたか             ⚠ Guest の継続的な行動履歴
```

⚠⚠ **「何を見たか」ではなく「機能が使われたか」まで。** ⚠ **この線を越えない。**

⚠ **[`0011`](0011-turn-on-a-field-test-mode-that-costs-two-promises-on-purpose.md) が
代償にした 2 つの約束は、⚠ 今度は 1 つも代償にしない。**

## 決定 4 — ⚠ どこに置き、⚠ いつ消えるか

⚠ **[`0031`](0031-give-the-issuer-a-daily-budget-because-the-issuer-is-a-continuing-subject.md)
の台帳に相乗りする。** ⚠ **1 つの部屋より長生きするものを 2 つ作らない**(`CLAUDE.md` § 3)。

⚠ **so 台帳と同じ規律が そのまま効く:**

```text
⚠ 00:00 UTC で 日付が変われば、⚠ 全部捨てて 0 から
⚠ 日をまたいで 何も残さない
```

### ⚠⚠ 「1 日で消す」と「傾向を見る」を どう両立させるか

⚠ **消してしまえば、⚠ 週をまたいだ傾向は見られない。** ⚠ **両立させる形は 1 つしかない:**

⚠⚠ **日が変わる瞬間に、⚠ その日ぶんの 集計値だけを ログに 1 行出して、⚠ 台帳からは捨てる。**

⚠ **ログに出るのは 数だけである** — ⚠ **ルーム id も、⚠ hash も、⚠ 誰についての何も入らない**
([`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 2)。
⚠ **so 出たあとの行は、⚠ 誰についての記録でもない。**

⚠ **これは「保存しない」を弱めていない** — ⚠ **弱めていたら、⚠ そう書く。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| ⚠ **Host 再利用率を測る** | ⚠⚠ **日をまたいで人を識別することになる**(⚠ Owner 判断 2026-09-09) |
| ⚠ **ルーム id を残して あとで突き合わせる** | ⚠ **「どのルームを作ったか」を持つことになる**(`../PRODUCT.md` § 5) |
| ⚠ **台帳とは別に 計測用の保存を作る** | ⚠ **1 つの部屋より長生きするものが 2 つになる**(`CLAUDE.md` § 3) |
| ⚠ **ポインタの座標を数える** | ⚠⚠ **何を指したかに 近づく。** ⚠ **回数までで止める** |
| ⚠ **画面共有の中身から何かを取る** | ⚠⚠ **論外。** ⚠ **`0001` と § 5 の中心である** |

## ⚠ 越えてはならない境界

```text
⚠ 数はルームについてであって、⚠ 人についてではない
⚠ 台帳の hash を 計測から見ない        ⚠ あれは枠のためだけである
⚠ 日をまたいで 台帳に何も残さない
⚠ ログに出るのは 数だけ                ⚠ id も hash も入らない
⚠ 「何を見たか」に一歩も入らない
⚠ Guest は数えない、⚠ 識別しない
```

## ⚠ しないと決めた主張

- ⚠ **「これで次に何を作るべきかが分かる」とは言わない。**
  ⚠ **数は「使われたか」までであり、⚠ 「なぜ」は人に聞かないと分からない**
  ([`../DISCOVERY.md`](../DISCOVERY.md) § 9)。
- ⚠ **割合を出すときは 分母を書く**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。
  ⚠ **「画面共有率 40%」は、⚠ 何ルーム中かを言わなければ 数ではない。**
- ⚠ **まだ 1 つも実装していない。** ⚠ **この ADR は決定であって、⚠ 測定ではない。**

## ⚠⚠ 実装したときに 半分で止めた(⚠ 2026-10-03)

⚠ **決定 2 の表のうち、⚠ サーバが もともと知っていることだけを 入れた。**

```text
⚠ 入れた   作られたルーム数            ⚠ 分母
          2 人が同時に居たルーム数      ⚠ 入口が成立したか
          ルーム継続時間(5 分未満 / 5〜20 分 / 20 分超)
          Host が閉じた / 誰も居なくなった

⚠ 入れていない  画面共有・ポインタ・camera・mute
               画面共有までの時間、⚠ 画面共有中の滞在時間
```

### ⚠ なぜ 止めたか — ⚠ [`0033`](0033-share-a-screen-where-it-can-be-shared-and-point-over-a-data-channel.md) と ぶつかる

⚠ **入れていない側は どれも ブラウザの中でしか起きない。** ⚠⚠ **サーバが知るには、⚠ ページが
サーバに言う必要がある。**

⚠ **[`0033`](0033-share-a-screen-where-it-can-be-shared-and-point-over-a-data-channel.md)
は それを 明示的に断っている:**

> ⚠ **シグナリングで送れば、⚠ kagima のサーバに「いつ画面を出し始めたか」という
> ⚠ 新しい事実を持たせることになる**

⚠ **だから あの ADR は データチャネルを選んだ。** ⚠ **ポインタの座標についても同じである。**

⚠⚠ **so この ADR の表と、⚠ あの ADR の決定は 両立しない。**
⚠ **粒度で逃げることはできる**(⚠ 「1 ルームにつき 1 ビット、⚠ 日が変われば消える」は
⚠ 「いつ始めたかの実況」ではない)— ⚠⚠ **が、それは 約束を 1 枚 削る判断であり、⚠ Owner のもの
である**(`CLAUDE.md` § 1: ⚠ **a feature that costs a piece of that promise is not a trade to
weigh — it is an owner decision, every time**)。

⚠ **so 止めた。** ⚠ **ファネルは 2 段で止まっている:**

```text
⚠ ルーム作成  →  通話開始  →  [画面共有]  →  [ポインタ利用]
   ⚠ 入った      ⚠ 入った      ⚠ 未決        ⚠ 未決
```

### ⚠ 読む口は 作っていない

⚠ **数を外に出す endpoint は 無い。** ⚠ **作れば それは 数を外に出す口である。**
⚠ **読めるのは、⚠ 日が変わるときに出る ログの 1 行だけである**(決定 4)。

⚠⚠ **so 配線が通っていることを確かめる手は、⚠ 書いたものを 読んでみることしかない** —
⚠ **部屋が書く形と 台帳が読む形を 1 か所に置き、⚠ 往復で突き合わせている**
(`src/quota/counts.ts` の `writeFacts` / `readFacts`、`CLAUDE.md` § 3)。

### ⚠ 区切りは コンセプトの言葉から 取った

⚠ **5 分未満 / 5〜20 分 / 20 分超。** ⚠ **分布を見るための区切りではない** —
⚠ **[`../PRODUCT.md`](../PRODUCT.md) § 1 が「5〜20 分」と言っていることが
当たっているかを 見るための区切りである。** ⚠ **so 区切りが動くのは、⚠ コンセプトが動くときである。**

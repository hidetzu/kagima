# 0029. ⚠ Guest を、⚠ その部屋にだけ効く印で戻す

- 状態: **決定**
- 日付: 2026-09-07
- 対象: ⚠ [kagima#90](https://github.com/hidetzu/kagima/issues/90)。
  ⚠ **[`0017`](0017-let-the-host-decide-who-comes-in-instead-of-a-passphrase.md) の
  「Host が居るときに決める」は動かない。** ⚠ **決め方ではなく、⚠ その判断を もう一度 使えるかが動く**

## 文脈

⚠ **実測 2026-09-06。** ⚠ **スマホの Guest を約 6 分 背面に置いた。** ⚠ **前面に戻した瞬間、
部品 9 個と `favicon.ico` を取り直している** — ⚠ **ブラウザがページごと捨て、⚠ 文書から作り直した。**
⚠ **Owner は自分で読み込み直していない**(確認済み)。

```text
20:09:36  ⚠ 通話が始まる
20:12:08  ⚠ メディアが落ちる
20:16:57  ⚠⚠ 前面に戻した瞬間、⚠ 9 個の部品を取り直す = ⚠ 文書ごと作り直し
```

⚠ **PC 側には `相手の接続が切れました` が出ており、⚠ Guest の socket ごと消えていた。**

⚠⚠ **[`0026`](0026-restart-ice-when-media-fails-and-signalling-has-not.md) と
[`0027`](0027-let-the-answerer-restart-too-after-waiting-longer.md) の張り直しは、⚠ この回では
効かない。** ⚠ **設計どおり秒まで正確に動いたうえで戻らなかった** — ⚠ **張り直す相手のページが
無かったからである。**

⚠ **いま在るもの:**

| 誰 | ⚠ ページを捨てられたあと |
|---|---|
| **Host** | ⚠ 戻れる。⚠ 端末に `{roomId, hostKey}` が 1 つある([`0021`](0021-keep-one-room-key-on-the-device-and-nothing-else.md)) |
| **Guest** | ⚠⚠ **もう一度ノックし、⚠ Host がもう一度「入れる」を押す** |

## 決定

⚠ **Guest にも、⚠ その部屋にだけ効く印を持たせる。** ⚠ **形は Host と同じにする。**

```text
Host   hostKey(端末に 1 つ) → POST /host-session   → 短命 token → socket   ⚠ 既にある
Guest  rejoin 印(端末に 1 つ) → POST /guest-session → 短命 token → socket   ⚠ これ
```

### ⚠ 印は署名された capability であって、⚠ 記録ではない

⚠ **サーバは何も新しく憶えない。** ⚠ **[`0023`](0023-write-the-minimum-so-a-room-outlives-its-sockets.md)
の「4 フィールド、⚠ ノックも token も名前も書かない」は動かない。**

⚠ **もし印をサーバに置けば、⚠ それは「誰かを入れた」という記録になる**
([`../PRODUCT.md`](../PRODUCT.md) § 5: ⚠ **誰がノックしたかを記録に残さない**)。
⚠⚠ **署名なら、⚠ 持っている側だけが持つ。**

### ⚠ join token とは 混ざらない

⚠ **payload の先頭に purpose を置き、⚠ 両方の検証がそれぞれの purpose を要求する。**

```text
join    join:{roomId}:{exp}:{nonce}:{role}
rejoin  rejoin:{roomId}:{exp}:{sessionId}:{role}
```

⚠⚠ **形は わざと 同じにする** — ⚠ **フィールド数も、⚠ 並びも。**
⚠ **最初の版は rejoin を 1 つ short にしていた。** ⚠ **変異で分かった: ⚠ `verifyJoinToken` から
purpose の検査を外しても 何も落ちなかった** — ⚠ **フィールド数が黙って仕事をしていたからである。**
⚠ **偶然で保っている分離は 分離ではない。** ⚠ **誰かがフィールドを 1 つ足した日に消える。**

⚠⚠ **`Role` に `rejoin` を足すことは しない。** ⚠ **`Role` は「この接続が部屋の中で何をしてよいか」
であり**([`0018`](0018-give-the-host-a-short-lived-role-inside-one-room.md))、
⚠ **足せば `authorizeUpgrade` が socket の役として受けてしまう。**

### ⚠ 失効は「部屋が死ぬこと」である

⚠ **交換のとき部屋の存在を確かめる。** ⚠ **部屋が無ければ、⚠ 印が正しくても短命 token は出ない** —
⚠ **そして refusal は `/host-session` と同じ 1 つの形である**
([`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 3)。

⚠ **so 長い印が出せるのは「その部屋が生きているあいだ」だけで、⚠ 実際に socket を開けるのは
2 分の join token のままである。** ⚠ **§ 4 の「短命な token」は動かない。**

### ⚠ 印は sessionId を運ぶ

⚠⚠ **これは飾りではない。** ⚠ **`src/signaling/hub.ts` は `sessionId` で「同じ参加者の張り直し」を
見分け、⚠ 古い socket を閉じてから席を数える。**
⚠ **新しい `sessionId` で戻ると、⚠ 半開きの古い socket が席を持ったまま `room-full` で弾かれうる** —
⚠ **その file が「トンネル越しにまさにこれが起きる」と書いている。**

### ⚠ 寿命は 2 時間、⚠ 入るたびに更新する

⚠⚠ **選んだ値であって、⚠ 測った値ではない**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。
⚠ **「Guest がどれくらい離席するか」は測っていない。** ⚠ **#90 にあるのは落ちていた時間(最長 512.5 秒)
だけで、⚠ 人が戻るまでの時間ではない。**

⚠ **20 分(`ROOM_IDLE_MS` と同じ)を却下した理由: ⚠ Host が居続ければ部屋は生きているのに、
⚠ 25 分 席を外した Guest の印だけが切れる** — ⚠ **現実に起きる場面で黙って効かなくなる。**

### ⚠ Host の画面は変えない

⚠ **Owner 決定 2026-09-07。** ⚠ **戻ってきた人を、⚠ 初めて入った人と同じ文言で扱う。**
⚠ **新しい文言は 1 つも増えない。**

⚠ **理由: ⚠ 「これはさっきの人だ」と画面で言うことは、⚠ 継続性を製品の機能として出すことである**
([`../PRODUCT.md`](../PRODUCT.md) § 5: ⚠ **利用者を継続的に識別する手段を持たない**)。
⚠ **落ちたことは今も `相手の接続が切れました` で見えているので、⚠ Host には「切れて、また
つながった」と見える。**

## ⚠⚠ これが弱める拘束を、⚠ 名指しする

⚠ **[`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 4 はこう書いている:**

> ⚠ **The Host's decision is exchanged for a short-lived token, once**, and
> ⚠ **nothing after that point re-reads the decision**

⚠⚠ **rejoin 印は、⚠ その判断を もう一度 使えるようにする。** ⚠ **`once` が動く。**

⚠ **動くのはそこだけである:**

```text
⚠ 判断そのもの     ⚠ 動かない。⚠ Host が居るときに、⚠ Host が決める(0017)
⚠ 誰が決めるか     ⚠ 動かない
⚠ token の短命さ   ⚠ 動かない。⚠ 2 分のまま
⚠⚠ once           ⚠⚠ 動く。⚠ 一度の判断が、⚠ その部屋のあいだ 何度か使える
```

⚠ **Owner 判断である**([`../PRODUCT.md`](../PRODUCT.md) § 6)。⚠ **2026-09-07 に受け取った。**
⚠ **`security.md` § 4 を書き換える** — ⚠ **弱めた拘束を元の文のまま残すと、⚠ コードと拘束が
食い違ったまま両方が正しく見える。**

## ⚠ 「継続的に識別しない」との関係

⚠ **[`0021`](0021-keep-one-room-key-on-the-device-and-nothing-else.md) が host key について
出した理屈が、⚠ そのまま使える:**

> ⚠ **1 つの扉であって、⚠ その部屋が終われば何も指さなくなる。**
> ⚠⚠ **ただし積み上がれば「この端末がいくつ部屋に入ったか」の記録になる。**

⚠ **so 条件も同じである: ⚠ 1 つだけ、⚠ 追記しない、⚠ 死んだら消す。**
⚠ **Host の印と Guest の印は別のキーに置く** — ⚠ **同じ端末が或る部屋の Host で別の部屋の Guest
でありうるため。** ⚠ **合わせて 2 つが上限で、⚠ それ以上は増えない。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| ⚠ **1. いまのまま** | ⚠ **実測で 4 回落ち、⚠ 最後は戻らなかった。** ⚠ **Owner 報告「長時間つないでいると手で入り直す必要がある」と回数が合う** |
| ⚠ **2. join token をページに持たせる** | ⚠⚠ **短命であることが token の目的そのものである**(`security.md` § 4)。⚠ **書き留めた時点でそれを失う** |
| ⚠ **4. Host に「戻ってきました」とだけ見せる** | ⚠ **押す手間は減るが、⚠ 捨てられるたびに Host の操作が要る点は変わらない。** ⚠ **そして「さっきの人」を画面で断言する** |
| ⚠ **印をサーバに置く** | ⚠⚠ **「誰かを入れた」という記録になる**(`PRODUCT.md` § 5)。⚠ **`0023` の 4 フィールドも動く** |
| ⚠ **`Role` に `rejoin` を足す** | ⚠⚠ **`authorizeUpgrade` が socket の役として受ける。** ⚠ **印がそのまま入場券になる** |
| ⚠ **寿命を 20 分(`ROOM_IDLE_MS`)にする** | ⚠ **Host が居続ければ部屋は生きているのに、⚠ Guest の印だけ切れる。** ⚠ **現実に起きる場面で黙って効かなくなる** |

## ⚠ 越えてはならない境界

```text
⚠ 印はその部屋にしか効かない            ⚠ 別の部屋で使えたら、⚠ 1 つの漏れが全部になる
⚠ 印は端末に 1 つ、⚠ 死んだら消す        ⚠ 積み上げれば記録になる(0021)
⚠ サーバは印を憶えない                  ⚠ 憶えれば「入れた人」の記録になる
⚠ 交換は部屋の存在を確かめる            ⚠ 部屋の死が失効である
⚠ refusal は /host-session と同じ 1 つ   ⚠ security.md § 3
⚠ 印と join token は purpose で分かれる  ⚠ 片方がもう片方として通ってはならない
⚠ 印は sessionId を運ぶ                 ⚠ さもないと戻った人が room-full で弾かれうる
⚠ 印と join token は 形が同じである      ⚠ 長さで分かれていたら、⚠ purpose の検査は飾りである
```

## ⚠ しないと決めた主張

- ⚠ **「これで Guest は必ず戻れる」とは言わない。** ⚠ **端末が `localStorage` を持たないことがあり**
  (`src/client/remember.ts` が既に扱っている)、⚠ **そのときはノックからやり直しである。**
- ⚠ **「2 時間が正しい」とは言わない。** ⚠ **測っていない。** ⚠ **選んだ値である。**
- ⚠ **「印が漏れても安全」とは言わない。** ⚠ **持っている者が使える bearer である。**
  ⚠ **限界は、⚠ 1 つの部屋、⚠ その部屋が生きているあいだ、⚠ 2 時間まで、である。**

## ⚠ 作りながら見つかった、⚠ この決定に必要だったもの

⚠ **どちらも #90 の文面には無い。** ⚠ **「Host の画面は変えない」を成り立たせるために要った。**

⚠ **1. 張り直しで置き換えられた socket が `peer-left` を出していた。**
⚠ **その人は去っていない** — ⚠ **戻ってきて、⚠ 古いほうが後から閉じただけである。**
⚠ **実測 2026-09-07: ⚠ Host の画面が Guest の名前を受け取り、⚠ 直後に消した。**
⚠ **`src/signaling/hub.ts` は同じ問いを relay については既に持っていた**(`stale`)。
⚠ **close については持っていなかった。**

⚠ **2. `peer-left` から回復する道が無かった。**
⚠ **`src/status/status.ts` は `peer-left` を「recoverable」と自分で書いていながら、
⚠ 一度立つと消えなかった。** ⚠ **ending は名前より強いので、⚠ 名前は届いても表示されない。**
⚠ **誰かが名乗ることが、⚠ その回復である。**

## 影響

- ⚠ **[`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 4 の `once` が書き換わる。**
- ⚠ **[kagima#90](https://github.com/hidetzu/kagima/issues/90) が閉じる。**
- ⚠ **Host 側の同じ穴は 閉じない。** ⚠ **`/host-session` は毎回 新しい `sessionId` を出すので、
  ⚠ 半開きの socket が席を持っていれば Host も `room-full` で弾かれうる。**
  ⚠ **この ADR の対象ではない。** ⚠ **見つけたことは記録しておく。**

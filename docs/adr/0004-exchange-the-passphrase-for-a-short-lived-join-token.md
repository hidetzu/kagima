# 0004. 合言葉はサーバ側で一度だけ検証し、短命な参加 Token と交換する

- 状態: **決定**
- 日付: 2026-09-04

## 決定

⚠ **合言葉の検証はサーバ側でのみ行う。**
⚠ **成功したら、そのルーム専用の短命な参加 Token を発行する。**
⚠ **以降、合言葉はどこからも読まれない。** ⚠ **WebSocket も、再接続も、Token だけで通す。**

⚠ **合言葉が違う場合と、ルームが存在しない場合は、外から区別できてはならない。**

## 文脈

- ⚠ **URL は我々が管理していない経路で相手に渡る。**
  ⚠ **URL が漏れただけでは入れない、という壁は合言葉ひとつだけである**
  ([`../PRODUCT.md`](../PRODUCT.md) § 3)。
- ⚠ **その合言葉は人間が口で言う。** ⚠ **だから短く、だから総当たりが効く。**
  ⚠ **強度を作っているのは合言葉ではなくレート制限である**
  ([`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 1, § 3)。
- ⚠ **合言葉を通話中ずっと持ち回すと、持ち回った先すべてが漏洩経路になる。**
  ⚠ **一度きりの交換にすれば、漏洩面は交換の瞬間だけになる。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **ブラウザ側で合言葉を照合する** | ⚠ **照合するには正解をブラウザへ送ることになる。** ⚠ **壁が消える** |
| **合言葉のハッシュを URL に載せる** | ⚠ **URL が漏れた時点で総当たりがオフラインでできる。** ⚠ **レート制限が意味を失う** |
| **WebSocket の接続ごとに合言葉を送る** | ⚠ **漏洩面が通話時間ぶん広がる。** ⚠ **再接続のたびに総当たりの機会が増える** |
| **Token に合言葉を埋める** | ⚠ **Token が漏れると合言葉も漏れる。** ⚠ **短命にした意味がなくなる** |
| **ルームが存在しないときだけ 404 を返す** | ⚠ **エンドポイントが「そのルームは在るか」を無料で答えることになる** |
| **Token をルームに紐付けない** | ⚠ **1 本漏れると全ルームに入れる** |

## ⚠ 越えてはならない境界

```text
合言葉、Token、TURN 資格情報を、ログに出さない
  ⚠ log(passphrase) ではなく log(body) / log(err) で漏れる
合言葉の比較は定数時間で行う
Token は発行されたルームでのみ有効である
拒否は、理由を区別できる形で数える(⚠ 数えていない拒否は、届かなかったのと見分けがつかない)
外から見て、合言葉違いとルーム不在は同じ応答・同じ形・同じ時間帯である
```

## ⚠ しないと決めた主張

- ⚠ **「合言葉は推測困難である」とは言わない。** ⚠ **言えるのは「語彙数^語数 = 何ビット」までで、
  その値はまだ決まっていない**([`../DISCOVERY.md`](../DISCOVERY.md) § 4)。
- ⚠ **「総当たりできない」とも言わない。** ⚠ **言えるのは「1ルームあたり何回まで、何秒で」だけで、
  その値もまだ決まっていない。**

## 影響

- ⚠ **Token の寿命が通話より短いと、通話中に切れる。**
  ⚠ **そのときに何が起きるかは決めなければならない**([`../DISCOVERY.md`](../DISCOVERY.md) § 5)。
  ⚠ **「たぶん起きない」は答えではない。**
- ⚠ **レート制限は、送信元単位とルーム単位の両方が要る。**
  ⚠ **ルーム単位だけだと、攻撃者が本物の Guest を締め出せる。**
  ⚠ **それは我々が自分で作った DoS である。**
- ⚠ **区別できない応答は、利用者にとっても区別できない。**
  ⚠ **画面の文言は `CLAUDE.md` § 4-1 の問題になる。**

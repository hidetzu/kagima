# 0018. Host 権限は、⚠ hostKey を一度だけ交換した短命な token が運ぶ

- 状態: **決定**
- 日付: 2026-09-06
- 決めた人: **Owner**
- 片付ける課題: [kagima#64](https://github.com/hidetzu/kagima/issues/64)

## 文脈

⚠ **[`0017`](0017-let-the-host-decide-who-comes-in-instead-of-a-passphrase.md) は
「Host が入れると決める」ことを入口そのものにした。** ⚠ **その決定が壁である。**

⚠⚠ **その壁を、⚠ 既に中に居る Guest が越えられた。**

⚠ **観測(2026-09-06、`src/` を無改変で走らせた):**

```text
⚠ guest が受け取った knockId: ijDMWT0o7RpeYAI4R18WCA
⚠⚠ 3 人目の状態: admitted / token: ⚠ 発行された
⚠⚠ その token でハンドシェイクは通るか: true
⚠⚠ 2 人目が抜けたあと 3 人目は: 接続した / 部屋の人数: 2
```

⚠ **欠陥は 2 つあり、⚠ 別々ではなかった。**

| | 何が欠けていたか |
|---|---|
| **通知** | ⚠ `hub.announce` が部屋の socket 全部に送っていた。⚠ **`knockId` を配っていた** |
| **admit** | ⚠ `session` が送り主を見ていなかった。⚠ **`knockId` さえあれば効いた** |

⚠⚠ **前者が 鍵 を配り、⚠ 後者が 鍵穴 を開けていた。**
⚠ **片方だけ直しても壁にならない** — ⚠ **通知だけ直せば「knockId を知らないから安全」であり、
⚠ それは壁ではない。**

⚠ **`ROOM_CAPACITY` は守りではない。** ⚠ **3 本目の socket は断るが、⚠ token は発行済みであり、
⚠ 誰かが抜けた瞬間に有効である。** ⚠ **そして 3 人目は `admitted` と表示され、⚠ カメラを
許可している**([`../PRODUCT.md`](../PRODUCT.md) § 3 が破れている)。

## 決定

⚠ **Host 権限は、⚠ その部屋の中だけの、⚠ 期限つきの役割とする。**
⚠ **人物の識別ではなく、⚠ アカウントでもない**(⚠ Owner の指定)。

```text
POST /api/rooms/{roomId}/host-session   { hostKey }  →  { token }   ⚠ role=host、⚠ 短命
```

- ⚠ **`hostKey` は 一度だけ 差し出され、⚠ 短命な token に交換される。**
  ⚠ **以後、⚠ 誰も `hostKey` を読み直さない。**
- ⚠ **役割は署名済み payload の中に入る。** ⚠ **so 改竄できない。**
- ⚠ **ノックの通知は、⚠ `role=host` の peer にだけ送る。**
- ⚠ **`admit` は、⚠ `role=host` の peer からだけ受ける。** ⚠ **他からは 黙って 捨てる。**

⚠ **これは新しい形ではない。**
⚠ **[`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 4 と
[`0017`](0017-let-the-host-decide-who-comes-in-instead-of-a-passphrase.md) が既に使っている形
そのものである** — ⚠ **決定を短命な token に一度だけ交換し、⚠ その後は決定を読み直さない。**

### ⚠⚠ 役割の無い token は、⚠ Guest ですらない

⚠ **`malformed` として拒む。** ⚠ **「役割が無ければ Guest」ではない。**

⚠ **理由: ⚠ 既定値は、⚠ 解析が間違っているすべての場所に効く。**
⚠ **そのうちの 1 つが、いつか host になる。** ⚠ **既定を置かなければ、その日は来ない。**

⚠ **知らない役割も同じである。** ⚠ **`role=admin` を「host ではないから guest」と丸めない** —
⚠ **閉じた集合に無ければ拒む。** ⚠ **3 つ目の役割が現れた日に、⚠ 丸めは黙って間違える。**

⚠ **この 2 つは実装で別々に効いており、⚠ 変異も別々に落ちる**
(`test/only-the-host-opens-the-door.test.ts`)。

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **A. `POST /api/rooms` が返す token に role を入れるだけ** | ⚠ **再接続で Host 権限が失われる。** ⚠ **token は `TOKEN_TTL_MS` で切れ、⚠ 取り直す経路が無い。** ⚠ **socket が一度落ちたら、⚠ その部屋にもう Host は居ない** |
| **B. ハンドシェイクのたびに hostKey を示す** | ⚠⚠ **`security.md` § 4 の逆をする。** ⚠ **`hostKey` は「部屋を閉じる」capability であり**(`DELETE /api/rooms/{id}`)、⚠ **接続のたびに線に載せると露出が増える。** ⚠ **しかも subprotocol は 応答ヘッダに反響される** |
| **D. 最初の socket を Host とする** | ⚠⚠ **壁にならない。** ⚠ **Host が落ちて戻ると Guest が Host になる。** ⚠ **`shareUrl` を持つ者が先に繋げば Host になれる** |
| **通知だけ直す** | ⚠ **`knockId` を知らないことに依る。** ⚠ **知られたら効いてしまう** |
| **admit だけ直す** | ⚠ **3 人目の nickname が Guest のブラウザに届いたままになる** |

## ⚠ 越えてはならない境界

```text
役割は 部屋 と 期限 に紐づく          ⚠ 人物にも、⚠ 端末にも、⚠ 接続にも紐づけない
hostKey は交換のとき以外 線に載らない  ⚠ そして交換の答えは、⚠ 間違いも 存在しない部屋も 同じ形
役割の無い token は 拒む              ⚠ 既定値を置かない。⚠ 知らない役割も拒む
Guest の admit には 何も答えない       ⚠ 答えれば「その knockId は実在する」と言うことになる
Host が居ないことを 外から見せない     ⚠ 0017 の性質を壊さない
```

⚠⚠ **最後の 1 行が、⚠ この変更で最も壊れやすい。**
⚠ **通知を Host だけにすると、⚠「Host が居ないと誰も受け取らない」状態が生まれる。**
⚠ **それが外から見えれば、⚠ ノックが「Host は席に居るか」を無料で答えることになる**
([`0017`](0017-let-the-host-decide-who-comes-in-instead-of-a-passphrase.md)、
[`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 3)。

## ⚠ しないと決めた主張

- ⚠ **「これで Host 権限が奪われない」とは言わない。**
  ⚠ **言えるのは「`hostKey` を知らなければ役割を得られない」までである。**
  ⚠ **`hostKey` を渡してしまった Host は、⚠ 渡した相手に権限を渡している。**
- ⚠ **「3 人目が入れない」とも言わない。**
  ⚠ **Host が入れると決めれば入れる。** ⚠ **それがこの製品である。**

## 影響

- ⚠ **`POST /api/rooms` が返す token は、⚠ Host の接続には使わない。**
  ⚠ **使えば役割が無く、⚠ Host が自分のドアを開けられない。**
- ⚠ **いま在る穴 —「Host の socket が落ちたら戻れない」— を、⚠ この経路が塞ぐ。**
  ⚠ **ただし クライアント側の自動再接続は この ADR の対象ではない。**
  ⚠ **経路が在ることと、⚠ ページが使うことは別である。**

# 0033. ⚠ 出せる側が画面を出し、⚠ 「ここ」はデータチャネルで送る

- 状態: **決定**
- 日付: 2026-09-09
- 対象: ⚠ **[`../PRODUCT.md`](../PRODUCT.md) § 1 と § 3 が 2026-09-09 に定めた「同じものを見て
  『ここ』と言える」を、⚠ どう成立させるか**

## ⚠⚠ 前提が 1 つ、⚠ 調べて崩れた

⚠ **出所: caniuse、⚠ 参照日 2026-09-09。**

```text
iOS Safari          ⚠ Not supported
Chrome for Android  ⚠ Not supported
Firefox for Android ⚠ Not supported
Samsung Internet    ⚠ Not supported
```

⚠⚠ **`getDisplayMedia` は モバイルブラウザで動かない。** ⚠ **例外を見つけられなかった。**

⚠ **そして kagima の実機は PC + スマホである。**
⚠ **[`../DISCOVERY.md`](../DISCOVERY.md) の H2(⚠ アプリを入れられない相手、⚠ 高齢の家族)は、
⚠ ほぼスマホの人である。**

⚠⚠ **so「共に見る(対称)」は、⚠ 画面共有だけでは 成り立たない。**

## 決定 1 — ⚠ 出せる側が画面を出し、⚠ 出せない側はカメラを向ける

⚠ **Owner 判断 2026-09-09。**

```text
⚠ PC     ⚠ 画面共有で「これを見て」
⚠ スマホ  ⚠ カメラを向けて「これを見て」
```

⚠⚠ **「同じものを見る」は 手段が端末で違うだけである。** ⚠ **どちらも 5〜20 分だけ開く。**
⚠ **v0.1.0 を PC 同士に絞ることは しない**(⚠ Owner 判断) — ⚠ **絞れば H2 が消え、
⚠ 別ネットワークの実測の構図も崩れる。**

### ⚠ 出せない端末に、⚠ 出せないボタンを見せない

⚠ **`navigator.mediaDevices.getDisplayMedia` が在るかどうかで決める。**
⚠⚠ **user-agent を読まない** — ⚠ **端末の名前で機能を推測するのは、⚠ 推測を測定として扱うこと
である**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。

⚠ **在るかどうかで ボタンを出す。** ⚠ **押せないボタンを出して 押させない。**
⚠ **どうしても言うときは、⚠ 何ができるかを言う**(`CLAUDE.md` § 4-1):

> ⚠ **この端末では画面を共有できません。⚠ カメラを向けて見せられます。**

⚠ **「対応していません」で終えない。** ⚠ **読む人の次の一手が そこに無い。**

## 決定 2 — ⚠ 2 本目の映像は、⚠ 最初から用意しておく

⚠ **[`../PRODUCT.md`](../PRODUCT.md) § 1 は「顔を見ながら話し、⚠ 同じ画面を見て」と言う。**
⚠ **so 顔と画面は 同時に要る。** ⚠ **`replaceTrack` で顔を差し替える形は 採らない。**

⚠⚠ **だが 2 本目を 共有が始まった時点で足すと、⚠ その場で再交渉が要る。**
⚠ **そして 誰が offer を出すかは 既に決まっている** — ⚠ **Guest が offer 側である**
(`public/room.html`)。⚠ **Host が共有を始めたら、⚠ 答える側が offer を出すことになる。**

⚠ **[`0026`](0026-restart-ice-when-media-fails-and-signalling-has-not.md) と
[`0027`](0027-let-the-answerer-restart-too-after-waiting-longer.md) は、⚠ その役割の上に
建っている。** ⚠⚠ **そこへ 再交渉を持ち込むと、⚠ 2 つの ADR に同時に触る。**

⚠⚠ **so 2 本目の transceiver は 通話を組み立てるときに 両方向ぶん 作っておく。**
⚠ **共有を始めるときは、⚠ 既に交渉済みの sender に `replaceTrack` するだけである。**

```text
⚠ 交渉は 1 回だけ            ⚠ 0026 / 0027 の役割に触れない
⚠ 共有の開始・停止は その場で ⚠ 待ち時間が無い
⚠ 代償                       ⚠ 使わない m-line が 1 本ぶん 常に乗る
```

⚠ **これが 目的を満たす いちばん小さい変更である**(`CLAUDE.md` § 7)。

### ⚠⚠ 作るのは offer 側だけである。⚠ 答える側は 受け取った m= 区画を もらう

⚠ **「両側で `addTransceiver` しておけば 3 本目どうしが噛み合う」— ⚠ これは 誤りだった。**

⚠ **根拠は RFC 8829 § 5.10。** ⚠ **remote offer を適用するとき、⚠ m= 区画と結びつけられるのは
⚠ `addTrack` で作られた transceiver だけである。** ⚠ **`addTransceiver` で作ったものは
⚠ 決して選ばれない。**

⚠ **実測 2026-09-09、Chromium、`npm run e2e --only=same-screen`:**

```text
⚠ 答える側の mid   0 / 1 / (無し) / 2
                            ↑ 自分で作った 3 本目。⚠ 最後まで結びつかない
                                      ↑ ブラウザが m2 のために作り直した recvonly
```

⚠⚠ **so 自分で作った 3 本目に `replaceTrack` しても、⚠ 画面は このページから出ていかない。**

⚠ **決めたこと:**

```text
⚠ offer 側     addTransceiver で 3 本目を作る
⚠ 答える側     作らない。⚠ offer が持ってきた m= 区画を そのまま使う
              ⚠ そして answer を作る前に direction を sendrecv にする
```

⚠ **`sendrecv` にするのは、⚠ ブラウザが作る m= 区画が `recvonly` だからである** —
⚠ **そのままだと 答える側は 見るだけで、⚠ 見せられない。**
⚠ **answer を作る前なら、⚠ これは 再交渉を伴わない。**

⚠ **「どちらが画面のほうか」は オブジェクトの同一性では決めない。**
⚠ **顔の transceiver を 通話を組み立てた時点で 数えておき、⚠ それ以外の映像が 画面である** —
⚠ **自分で作った側でも、⚠ もらった側でも 同じ判定になる。**

## ⚠⚠ 決定 3 — ⚠ 「ここ」は データチャネルで送る。⚠ 我々を通さない

⚠ **ポインタの座標は シグナリングでも運べる。** ⚠⚠ **運ばない。**

| ⚠ 理由 | |
|---|---|
| ⚠⚠ **座標は「何を指したか」である** | ⚠ **[`0032`](0032-count-what-was-used-never-what-was-seen.md) は「ポインタが指した内容」を測らないと決めた。** ⚠ **我々を通れば、⚠ 測れる場所に置くことになる** — ⚠ **測らないと決めたものを、⚠ 通り道に置かない** |
| ⚠ **[`0001`](0001-keep-media-peer-to-peer-and-off-our-servers.md) の筋** | ⚠ **2 人のあいだで起きることは 我々を通らない。** ⚠ **画面が通らないのに 指した先が通るのは 筋が通らない** |
| ⚠ **[`0031`](0031-give-the-issuer-a-daily-budget-because-the-issuer-is-a-continuing-subject.md) の枠** | ⚠ **シグナリングのメッセージは 20:1 で requests に効く。** ⚠ **ポインタは 秒に何度も動く** |

⚠ **`RTCDataChannel` は 既にある `RTCPeerConnection` の上に乗る。** ⚠ **新しい依存は無い。**

⚠ **送るのは 相対座標と、⚠ どの絵についてかだけである。**
⚠ **画素も、⚠ 画面の内容も、⚠ 何も送らない。**

### ⚠⚠ 指せる面は 2 つある(⚠ Owner 決定 2026-09-09)

⚠ **決定 1 で「スマホは カメラを向けて『これを見て』」と決めた。**
⚠⚠ **so 見せている側がスマホなら、⚠ 「ここ」の指す先は カメラ映像である。**
⚠ **共有画面だけに置くと、⚠ [`../DISCOVERY.md`](../DISCOVERY.md) の H2 の側に 「ここ」が無くなる。**

```text
⚠ 共有画面      ⚠ 出している側にも 自分の共有画面を出す
⚠ カメラ映像    ⚠ 顔を出している側の画にも 点が乗る
```

⚠⚠ **出している側にも 自分の共有画面を返す。** ⚠ **でないと、⚠ 相手の「ここ」が乗る面が
こちらに無い。** ⚠ **代償は、⚠ 画面全体を共有したときの 入れ子の映り込みである** —
⚠ **承知の上で受け入れた。**

### ⚠ 誰が指しているかは、⚠ 送らない

⚠ **ルームには 2 人しか居ない**([`../PRODUCT.md`](../PRODUCT.md) § 3)。
⚠ **so 「自分の / あなたの」で 両方を言い切れる。** ⚠ **名前は 線に乗らない。**
⚠ **受け取った側が 自分の言い方に読み替える**(`src/call/pointer.ts` の `flipPoint`、
⚠ **裏返しを 2 回かけると 元に戻ることを検査している**)。

### ⚠⚠ 指では、⚠ 押しているあいだしか 出ない(⚠ 実測 2026-09-11)

⚠ **Owner の報告(⚠ 実機、⚠ 2026-09-11): ⚠ 「⚠ ポインタは、⚠ 共有エリア内でクリックしてから、
⚠ 見えるようになった」。**

⚠ **測った(⚠ Chromium、⚠ `npm run e2e`、⚠ 指の入力として):**

```text
tap が出すもの   pointerdown / pointerup / pointerout / pointerleave
                ⚠⚠ pointermove は 1 つも出ない
```

⚠ **マウスは 押さずに動く。** ⚠ **指は 押していないあいだ 存在しない。**
⚠⚠ **so 滑らせない tap は 何も送っていなかった** — ⚠ **「クリックしてから」は そういうことである。**

⚠ **`pointerdown` でも送るようにした。** ⚠ **どの見せ方を採っても、⚠ 触れた場所は
「指した場所」である。**

### ⚠⚠ 指を離しても、⚠ 数秒だけ残る(⚠ Owner 決定 2026-09-11)

⚠ **指は 押しているあいだしか存在しない。** ⚠⚠ **so すぐ消すと、⚠ 相手が顔を上げる前に
「ここ」が終わっている** — ⚠ **そしてそれが、⚠ この機能の存在理由そのものである。**

```text
⚠ 指を置く    点が出る
⚠ 指を離す    ⚠⚠ 残る
⚠ 3 秒後      消える
```

⚠ **`POINT_LINGERS_MS`(`src/client/pointing.ts`)。**
⚠ **マウスも同じ扱いにする** — ⚠ **1 つの振る舞いは 1 つの説明で済み、⚠ 約束も同じである:
⚠ 指した場所は しばらく残る。**

⚠ **却下: ⚠ 次に触るまで残す。** ⚠⚠ **それは ポインタではなく 印である**
(⚠ [`../PRODUCT.md`](../PRODUCT.md) § 3: ⚠ **高機能なホワイトボードは v0.1.0 に入れない**)。

⚠ **指しなおしたら、⚠ 仕掛けてあった「手放す」は 取り消す。**
⚠ **マウスが縁を跨ぐたびに起きる並びであり、⚠ 消し忘れると いま指している点が 3 秒後に
勝手に消える**([`change-review`](../../.claude/skills/change-review/SKILL.md) § 4:
⚠ **条件が変わったのに 仕掛けたままの timer**)。

### ⚠ 順を保証しない。⚠ 代わりに 何番目かを送る

⚠ **`RTCDataChannel` を `ordered: false` で開く。**
⚠ **落ちた 1 つが 次の位置を 後ろで待たせるのは、⚠ 手より遅れて追いつく点になる。**

⚠⚠ **so 古い位置が 新しい位置を 上書きしうる**
([`change-review`](../../.claude/skills/change-review/SKILL.md) § 4)。
⚠ **番号を付け、⚠ 大きいものしか採らない。**
⚠ **「指を離した」は 値であって、⚠ メッセージが無いことではない** —
⚠ **届かなかったことと 送られなかったことは 別である**
([`evidence.md`](../../.claude/rules/evidence.md))。

### ⚠⚠ 同じ経路が 運ぶのは 「いま何を出しているか」である

⚠ **実測 2026-09-09、Chromium: ⚠ 送る側が `replaceTrack(null)` しても、⚠ 受け側の track は
⚠ live のまま、⚠ `muted` にもならない。** ⚠ **`<video>` は 最後のフレームを 30 秒 保持し続けた
(⚠ そこで待つのをやめた ― ⚠ これは「30 秒後に消える」という測定ではない)。**

⚠⚠ **so 「共有をやめた」は メディアからは読めない。** ⚠ **言うしかない。**

⚠ **言い方は 決定 3 と同じ経路である** — ⚠ **`RTCDataChannel`、⚠ 我々を通さない。**
⚠ **シグナリングで送れば、⚠ kagima のサーバに「いつ画面を出し始めたか」という
⚠ 新しい事実を 持たせることになる**(`CLAUDE.md` § 3: ⚠ **制御面は 誰が入れるかだけを運ぶ**)。

⚠⚠ **同じことが 決定 4 の カメラと mute にも起きる。** ⚠ **カメラを切ると track を止めるが
(§ 決定 4)、⚠ 受け側の track は やはり live のままで、⚠ 顔が 最後の絵のまま残る。**
⚠ **so 運ぶのは 3 つである:**

```text
showing      ⚠ 画面を出している
camera       ⚠ カメラが入っている
microphone   ⚠ マイクが入っている
```

⚠⚠ **毎回 3 つとも 送る。** ⚠ **「何が変わったか」ではなく 「いまどうなっているか」である** —
⚠ **同じ通知が 二度届いても、⚠ こちらが選んでいない順で届いても、⚠ 読む側は同じ場所に立つ。**

⚠ **向きは 1 つに揃えてある。** ⚠ **どの欄も「いま出て行っているか」である。**
⚠ **製品の言葉は「mute」だが**(`../PRODUCT.md` § 3)、⚠ **それは `microphone: false` であって、
⚠ 「mute」という語は 画面のもので、⚠ 線の上のものではない。**

⚠ **何を出しているかは 送らない。** ⚠ **画素も、⚠ 画面の内容も、⚠ 座標の指す中身も 送らない。**
⚠ **相手のブラウザから来る以上 敵性入力であり、⚠ 形が違えば 黙って捨てる**
(`src/call/notice.ts`、`test/notice.test.ts`)。
⚠⚠ **欄が 1 つ欠けていたら、⚠ 通知ごと捨てる。** ⚠ **欠けた欄を `false` と読むと、⚠ 「相手が
言わなかった」が 「相手が切ったと言った」になる**
([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md) § Silence is not permission)。

## ⚠ 決定 4 — ⚠ カメラを切るのは 止めること。⚠ mute とは違う

⚠ **[`../../.claude/rules/security.md`](../../.claude/rules/security.md) § 5:**

> ⚠ **Stop the tracks, not just the UI.** ⚠ **A hidden `<video>` with a live track is a camera
> that is still on**, ⚠ **and the tally light is the only thing the user can see.**

| | ⚠ どうするか | ⚠ なぜ |
|---|---|---|
| ⚠⚠ **camera off** | ⚠ **track を止める** | ⚠ **点いたままのランプは、⚠ 利用者に見える唯一の事実である** |
| ⚠ **mute** | ⚠ **track を `enabled = false` にする** | ⚠ **音は出て行かない。** ⚠ **止めると 戻すのに再取得が要り、⚠ mute は頻繁に押される** |
| ⚠ **画面共有をやめる** | ⚠ **track を止める** | ⚠ **camera と同じ。** ⚠ **ブラウザの共有バーが 利用者に見える事実である** |

⚠⚠ **2 つが違うことを 書いておく。** ⚠ **同じに見えて 違い、⚠ 違う理由がある。**

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| ⚠ **顔を画面共有に差し替える(`replaceTrack` 1 本)** | ⚠ **§ 1 が「顔を見ながら話し、⚠ 同じ画面を見て」と言っている。** ⚠ **片方が消える** |
| ⚠ **共有開始時に 2 本目を足して再交渉** | ⚠⚠ **答える側が offer を出すことになり、⚠ `0026` / `0027` に同時に触る** |
| ⚠ **両側で 2 本目を `addTransceiver` して 噛み合わせる** | ⚠⚠ **噛み合わない。** ⚠ **RFC 8829 § 5.10 は `addTrack` で作られたものしか結びつけない**(⚠ 実測 2026-09-09) |
| ⚠ **共有の停止を 受け側で 見て取る(`muted` を待つ)** | ⚠⚠ **`replaceTrack(null)` では `muted` にならない**(⚠ 実測 2026-09-09)。⚠ **最後のフレームが残り続ける** |
| ⚠ **共有の停止を シグナリングで伝える** | ⚠ **サーバに「いつ画面を出したか」を持たせることになる**(`CLAUDE.md` § 3) |
| ⚠ **通知を「変わった欄だけ」にする** | ⚠ **二度届いたとき・⚠ 順が入れ替わったときに 読む側が どこに立つかが 定まらない。⚠ 毎回 全部 送れば その問いが消える** |
| ⚠ **欠けた欄を `false` と読む** | ⚠⚠ **「言わなかった」が「切ったと言った」になる**(`evidence.md`)。⚠ **何も起きていない通話から 顔が消える** |
| ⚠ **ポインタを 共有画面だけに置く** | ⚠ **Owner 却下 2026-09-09。** ⚠⚠ **決定 1 で スマホは カメラを向けて見せると決めた以上、⚠ H2 の側に「ここ」が無くなる** |
| ⚠ **出している側に 自分の共有画面を返さない** | ⚠ **Owner 却下 2026-09-09。** ⚠ **相手の「ここ」が乗る面が こちらに無く、⚠ 指すのが 片道になる** |
| ⚠ **ポインタを 順序保証つきで送る** | ⚠ **落ちた 1 つが 次の位置を 後ろで待たせる。⚠ 手より遅れて追いつく点は、⚠ 指していない場所を指す** |
| ⚠ **範囲外の座標を 0..1 に丸める** | ⚠⚠ **意味の無い値が 「隅を指した」になる。** ⚠ **捨てるほうが 正直である** |
| ⚠ **誰が指しているかを 送る** | ⚠ **2 人しか居ないので 要らない。** ⚠ **名前を 線に乗せない** |
| ⚠ **ポインタを シグナリングで送る** | ⚠⚠ **測らないと決めたものを 通り道に置く**(`0032`)。⚠ **`0031` の requests にも効く** |
| ⚠ **user-agent で 画面共有の可否を決める** | ⚠ **端末の名前で機能を推測することになる**(`evidence.md`) |
| ⚠ **camera off を `enabled = false` で済ませる** | ⚠⚠ **ランプが点いたままになる**(`security.md` § 5) |
| ⚠ **v0.1.0 を PC 同士に絞る** | ⚠ **Owner 却下。** ⚠ **H2 が消え、⚠ 別ネットワークの実測の構図も崩れる** |

## ⚠ 越えてはならない境界

```text
⚠ 画面も 音も 座標も 我々を通らない        ⚠ 0001、0033 決定 3
⚠ ポインタは 座標と どの絵かだけ           ⚠ 画素も内容も 誰かも送らない
⚠ camera off と 画面共有の停止は track を止める  ⚠ security.md § 5
⚠ 交渉は 1 回                              ⚠ 0026 / 0027 の役割に触れない
⚠ 3 本目を作るのは offer 側だけ             ⚠ RFC 8829 § 5.10
⚠ 「いま何を出しているか」も 我々を通らない   ⚠ 決定 3 と同じ経路。⚠ showing / camera / microphone
⚠ 機能の有無で分岐する                     ⚠ user-agent を読まない
⚠ 出せない端末に 出せないボタンを見せない
```

## ⚠ しないと決めた主張

- ⚠ **「モバイルでは画面共有できない」を、⚠ kagima の欠点として書かない。**
  ⚠ **ブラウザが持っていない機能であり、⚠ 我々の実装の穴ではない**(`CLAUDE.md` § 4-1)。
  ⚠ **同時に、⚠ 「相手の端末が悪い」とも書かない。**
- ⚠ **「同じものを見る が成立する」とは まだ言わない。** ⚠ **実装も、⚠ 実機も、⚠ 計測も無い。**
- ⚠ **ポインタが「使われる」とも言わない。** ⚠ **それを測るのが
  [`0032`](0032-count-what-was-used-never-what-was-seen.md) である。**

## 影響

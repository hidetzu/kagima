# 0012. 診断はアドレス種別だけを言い、それ以上は言わない

- 状態: **決定**
- 日付: 2026-09-05
- 決めた人: **Owner**

## 文脈

⚠ **実測で、両端そろった観測が `selected pair: host/host over udp` を出した**
([`../FIELD-TEST.md`](../FIELD-TEST.md))。
⚠ **スマホの Wi-Fi はオフだった。**

⚠ **IPv4 の `host/host` と IPv6 の `host/host` は、⚠ 別の観測である。**
⚠ **しかし計器は、⚠ その 2 つをまったく同じ 1 行として記録していた。**

⚠ **別のものが同じに見えるなら、⚠ 記録として使えない。**
⚠ **これは「どちらが何を意味するか」の話ではない** — ⚠ **意味づけは、⚠ どう試験したかを知って
いる人がする。** ⚠ **計器の仕事は、⚠ 違うものを違うものとして残すことである。**

## 決定

⚠ **診断は、⚠ candidate ごとに `v4` / `v6` / `?` のいずれか 1 語を出す。**
⚠ **アドレスそのものは、⚠ 保持も出力もログもしない。**

⚠ **見てよいのは `familyOf` 1 箇所だけであり、⚠ 返り値はその 3 語しかない。**

## ⚠ 計器は原因を言わない

⚠ **この ADR は種別を出すことだけを決める。** ⚠ **種別から何かを結論することは決めない。**

⚠ **`v6` の `host/host` は「越えるべき NAT が無かった」を意味しない。**
⚠ **IPv6 のある同一 LAN 上の 2 台でも、⚠ まったく同じ pair が成立する。**
⚠ **so レポートはその一文を出さない** — ⚠ **一度は出していたが、⚠ 外した。**

⚠ **同じ理由で、⚠ verdict は原因を名指さない:**

```text
前   ⚠ 「srflx はあるが pair が無い: NAT を越えられなかった」
今   ⚠ 「candidates gathered, no ICE pair selected (cause undetermined)」
```

⚠ **どこまで進んだかは観測できる。** ⚠ **なぜそこで止まったかは、⚠ 計器には見えない。**
⚠ **計器が原因を名指すと、⚠ 我々の推測が測定値として記録に入り、
⚠ 次にそれが記録から証拠として読み出される**
([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。

⚠ **`test/diagnostics.test.ts` が、⚠ どの verdict も `NAT` という語を含まないことを検査する。**

## ⚠ 壁の形が変わった。弱くなってはいない

```text
前   ⚠ 「address という語がソースに出てこない」
今   ⚠ 「address を読むのは 1 関数だけ」
   + ⚠ 「その関数は 3 語しか返せない」
   + ⚠ 「レポートに住所が出ない」(⚠ 前からある。⚠ 変えていない)
```

⚠ **狭い例外は、⚠ 切り出して残りを検査することで狭いままになる。**
⚠ **`test/diagnostics.test.ts` は `familyOf` の定義と呼び出しを削り、⚠ 残りに `address` が
1 つも無いことを確かめる。** ⚠ **`.address` の直接読み出しは、⚠ どこであれ禁止である。**

⚠ **変異検査で 3 通りとも落ちることを確認した:**

| 変異 | ⚠ 落ち方 |
|---|---|
| `familyOf` がアドレスをそのまま返す | ⚠ `familyOf leaked something from …` |
| 収集器が `familyOf` を通さない | ⚠ `the collector names an address outside familyOf` |
| レポートが語彙を通さず出す | ⚠ `an address reached the report` |

## ⚠ `?` は失敗ではない

⚠ **mDNS の `.local` candidate は種別を隠す。** ⚠ **そのときは `?` と言う。**
⚠ **推測しない**([`../../.claude/rules/evidence.md`](../../.claude/rules/evidence.md))。

## 却下した案

| 案 | ⚠ 却下の理由 |
|---|---|
| **何も出さず、Owner が `webrtc-internals` で毎回確認する** | ⚠ **別々の観測が同じ 1 行として残り続ける。** ⚠ **そして `webrtc-internals` には生アドレスが全部出る** |
| ⚠ **種別ではなく「NAT を越えたか」を出す** | ⚠ **判断をこちらが埋め込むことになる。** ⚠ **後から検証できない。** ⚠ **観測と推論を分ける原則に反する**(`CLAUDE.md` § 7) |
| **アドレスを出し、貼るときに人が消す** | ⚠ **人が消し忘れる。** ⚠ **貼れるように作る、が計器の要件だった** |
| **prefix だけ出す**(`2400:4050::/32` など) | ⚠ **prefix は回線を特定しうる。** ⚠ **1 ビットで足りるものに、それ以上を出す理由が無い** |

## ⚠ しないと決めた主張

- ⚠ **「IPv6 なら TURN は要らない」とは言わない。**
- ⚠ **「`v6` の `host/host` だから別ネットワークだった」とも言わない。**
  ⚠ **言えるのは「両端の IPv6 host candidate が直接届いた」までである。**
  ⚠ **別ネットワークだったかどうかは、⚠ 試験した人の証言であって、⚠ 観測ではない。**
- ⚠ **IPv4 しか無い経路については、⚠ 相変わらず何も測っていない。**
- ⚠ **`?` を「IPv4 だろう」と読み替えない。**

## 影響

- ⚠ **`docs/FIELD-TEST.md` の表を「観測」と「原因」に分けた。**
  ⚠ **前の表は `host/host` からネットワーク構成を決めていた。** ⚠ **決められない。**
- ⚠ **レポートは `host/host over udp v6` の形になる。** ⚠ **それ以上は言わない。**
